# Worldgoing 3D 裝備製作與編輯器接入

交付是可在角色編輯器選取、旋轉、播放動畫的真實裝備，以及已親自檢查的最新預覽圖。參考圖、Blender 圖、GLB 匯出成功、測試 PASS 各自只證明部分結果。

## 先確認這次任務

1. 明確列出目標部件、參考圖、替換或新增選項、適用男女、風格。沿用使用者已給的選擇；可獨立完成的工作先做。
2. 找到包含 `project.godot` 的專案根目錄。閱讀根目錄 `HUMANBASE_V1_3D_PIPELINE_HANDOVER.md`，並讀本技能 [references/pipeline.md](references/pipeline.md)。文件是起點，當前建置腳本、GLB 與編輯器才是核對實際行為的依據。
3. 檢查工作樹與目標函式，保留他人修改。記錄既有素材檔案時間與部件名稱；有必要時建立本次目標檔案的可恢復備份。不要清空整個資產目錄。
4. 用圖片檢視工具親自看參考圖與目前模型。圖片上的「PBR」「Clean Topology」「Game Ready」只是標示，不是已驗證的資產品質。

## 從參考圖建立形狀

- 先按部件選路線：貼身衣物用表面提取／適配；硬甲用獨立曲面與關節覆疊；長披風、袍裙等離身軟布先讀 [references/cloth-cape.md](references/cloth-cape.md)。不要將硬護肩掛接或貼身褲子權重直接套到長布料。
- 拆成可辨識部件，先處理輪廓、比例、厚度，再處理接縫、扣具與雕花。裝備設計適配目前素體，不能為了塞進裝備擅自改體型、臉、頭髮。
- 三視图不一致時，以同一素體和合理結構解決遮擋與透視差；記錄推定處，不把透視圖當成精確正交尺寸。
- 先在 Blender 中展示素體與粗模的正面、側面、背面。轮廓尚未像參考時，先修大形，不能以大量鉚釘裝飾掩蓋。
- 合身衣物、內靴、護腕：複製對應身體／來源衣物表面，保留原有權重，或對新拓撲傳遞權重。先確認材質槽內容再提取；以平面切割或整理邊環取得乾淨邊界，單靠面中心篩選容易產生鋸齒。
- 裝甲板、護肩、鞋底、扣具：建立符合輪廓的獨立網格。關節處採分段覆疊或合理蒙皮。圓柱只適合粗模，不能直接充當最終靴子；鞋子必須有腳背、腳尖、腳跟、鞋底與收束靴筒。
- 大輪廓與側面可見厚度用幾何；微小皮紋、刮痕可用貼圖。先確認最終材質路徑會讀取貼圖，避免白做細節。
- 輪廓、動作、材質各保留可檢查的階段產物：灰模四視圖通過後才製作裝飾；用短動作確認形變匯出；用帶 UV 的材質樣片確認引擎路由後才製作完整貼圖。這些是工作內部檢查，不自動要求使用者逐階段批准。
- 槽位模組化不等於每條邊線都需要獨立物件。連續布面可使用多材質；保持可編輯來源，重建不得覆蓋已完成的美術調整。

## 貼合與骨骼

- 在 Rest Pose 量測素體與內層裝備的實際座標、截面和表面法線。不要照抄舊文件的固定深度；曾有胸甲整片被埋進身體，卻仍成功匯出。
- 區分物件局部、骨骼局部與世界座標，以及 Blender Z-up 和 Godot Y-up。由匯入／匯出器處理軸轉換，不重複補轉 90 度。
- 軟部件保留或傳遞原生權重，清理未綁頂點並正規化。硬部件沿用專案既有骨骼掛接 helper，確認 Rest Pose 變換，避免同時骨骼親子與 Armature 造成雙重變換。
- 原生權重是起點，不保證不同輪廓或所有動作零穿模。離身下襬按受力區與活動空間設計形變，必要時用局部形態校正；不能只按高度分配骨盆權重便宣稱完成。
- 靴筒跟小腿、鞋身跟腳部；跨踝處以分段或過渡權重處理。整隻高靴綁單一骨骼通常不能通過腳踝彎曲檢查。
- 逐層檢查素體→內衣／褲子→裝備。正確偏移取決於表面與動作；不能用刪除全部身體或縮小體型解決穿模。既有身體遮罩只可按衣物覆蓋範圍處理，選「無」後必須恢復。
- 男、女各自貼合與測試，不能把男裝等比例縮放後直接宣稱支援女裝。

## 接入與驗收

依 pipeline 參考完成 builder 呼叫、輸出清單、GLB、Godot 重匯入、選項 ID／名稱前綴、材質与顯示路由。新增選項時保留原有選項；替換時沿用已約定 ID。

長任務的要求是有界執行、可追蹤及可停止，不依賴固定名稱的工具。啟動前核對當前可呼叫的工具及專案規則；不要把其他環境的 `schedule`、`manage_task` 等名稱當成必定存在的介面。

- 優先沿用具硬性逾時的 runner。Blender 可由子程序逾時機制限制執行時間，並加 `--python-exit-code 1`，避免 Python 例外仍回報退出碼 0；Godot 使用可用的有界驗證入口。
- 若呼叫轉入背景，保存實際返回的程序／工作 ID，使用該環境提供的狀態或等待介面持續檢查，直到完成、失敗或逾時。僅設定等待時間不等於已限制子程序生命週期。
- 有可用計時工具且專案要求時就使用；缺少時採硬性逾時加持續檢查。若上層專案規則明文要求指定工具，先取得替代方式的授權；同一任務已取得的授權沿用，不反覆詢問。技能不能自行覆寫專案規則。
- 逾時後停止本次啟動的程序並保留日誌、候選與備份；先查原因，不無限重試。沒有可用的停止／監控方式，或需要新的執行權限時才暫停請示。不可宣稱設定了不存在的計時器。

驗證 Godot 時使用可用的 `godot-runtime-verify` 技能。測試退出碼 0 與新截圖只代表執行完成；必須另外逐張看圖：

美術圖與遊戲尺度圖分開。建議全身美術圖至少 1024 像素、人物佔高 70–85%，並有接縫近景；依資產大小調整，以細節確實可判讀為準。動畫使用完整短片／可播放幀序列及極值幀，固定秒數不保證取到最大屈膝。圖片太小、被裁切或姿態未生效，記「不可判讀」，不能算通過。中性姿態四視圖要核對角色朝向，不以扭身 idle 的 yaw=0 代替正視圖。

| 驗收項目 | 所需證據 |
| --- | --- |
| 形狀像參考 | 素體穿戴正／背／側／3⁄4 圖；比較靴高、腳尖、甲片層次等具體特徵 |
| 能在編輯器使用 | 目標選項可選、有真實網格，切換其他裝備與無後不殘留 |
| 動畫貼合 | 實際可用 idle／walk／run 與相關大幅动作，多個關鍵幀，包含踝／膝最大彎曲 |
| 組合相容 | 單件、與內層衣物、與完整裝備；男女分開檢查 |
| 外觀未被破壞 | 臉、身體、材質、陰影與地面接觸正常；無黑臉、浮空、漏面 |
| 可重建 | 明確建置入口、輸出檔與實際測試結果；預覽時間晚於本次輸出 |

看見穿模、鋸齒缺口、漂浮、粗模形狀不符時，回到對應建模或接入步驟修正。不得把「測試 PASS」寫成「無穿模」；無法修完就列出具體未通過項目與圖，不標記完整驗收。

按匯出、功能、輪廓、材質、動作、組合各記「通過／失敗／未測／不可判讀」。歷史手冊中的固定尺寸、動作數及「100%」「徹底零穿模」不是當前證据。引用具體圖、版本和檢查範圍，不用物件數／三角面數代表美術品質。
