## 0. 一句話設計

勢力是「誰跟誰是同一邊」的唯一單位。新增一份放在 Region Slot 的**勢力名冊**，給每個勢力名字、顏色、首長和（可選的）一個國家；Site 裡仍只存 `faction_id` 數字，不改既有判敵與權限程式。勢力的誕生、合併、分裂、消滅都只改名冊，再由各 Site 在載入時套用。

## 1. 現況盤點

### 1.1 勢力現在是什麼

勢力只是一個整數 `faction_id`，沒有名字、首長、顏色或任何上層紀錄（grep `faction_name`／`FACTION_COLOR` 無結果）。它出現在五種地方：

| 位置 | 欄位 | 依據 |
| --- | --- | --- |
| 單一人物 Actor | `faction_id` | `terrain_lab.gd:200`、`terrain_test_character.gd` |
| 隊伍 TerrainArmy（整隊一個值，逐人沒有） | `faction_id` | `terrain_lab.gd:219`、`:225`；職位計畫 §8 第 284 行明說 Army rows 沒有逐人 faction |
| Crowd 名冊／群眾隊伍 | `faction_id`、`team.faction` | `site_store.gd:1362`、`:1458` |
| 建物 | `owner_faction`（-1＝無主） | `site_runtime.gd:1739`、權限檢查 `:1449`、`:1483` 等 |
| 聚落 | `settlement.owner_faction`、陷落計時 `contest_faction` | `site_settlement.gd:33`、`:407` `fall_to` |

另外拘押、車輛接收、跨 Site 旅行帶的組織引用也記 faction（`site_store.gd:1096`、`:1173`；`site_equipment_orders.gd:2771` `_portable_factions`）。上限 `MAX_FACTION = 100000000`（`site_settlement.gd:23`）。

### 1.2 勢力怎麼被指定

- 測試／開局：玩家隊 0、對手 1、第三隊 2，寫死在 `terrain_lab.gd:219`、`:225`；`site_technology_artisans.gd:19-22` 同樣寫死 0／1／2。
- 會改動 faction 的現有路徑只有三條：聚落陷落把管轄內建物換給攻方（`site_settlement.gd:407-417`）、車輛接收把接收方設成來源方（`terrain_lab.gd:3927`）、駐軍合併（`site_garrison.gd:326`）。**人物沒有任何正式的改勢力入口。**
- 沒有「建立新勢力」的地方；新數字只能由情境或測試寫入。

### 1.3 敵我判定

不同勢力一律敵對、同勢力一律友好，沒有中立或和平。判敵與同方檢查散在 12 個非測試檔、約 39 處（以 `faction(_id)? == / != …faction` grep 計數，屬近似值），例如 `terrain_lab.gd:4813` 找敵人、`region_travel_site.gd:11` 出發守衛、`region_save_slot.gd:5031-5070` Region 到站開戰（三方以上直接不建 battle）、C# `compiled_exchange_candidates.cs`。貿易規劃 §5.5 已計畫新增 `SiteFactionRelations.hostile(a, b)` 單一入口，只換「是否敵對」，不換「是否同一方」。

### 1.4 國家與勢力沒有綁在一起

- 國家紀錄存在**各 Site 自己**的 `terrain.site.equipment_nations[nation_id]`，只有 `members`、`standards`、`culture`、`offices` 等鍵，沒有勢力欄位（`site_equipment_orders.gd:45`、`:841` `_member`）。人物旅行到別的 Site 時，靠 `organization_refs` 帶「遠端國家」引用（`site_equipment_orders.gd:2808`），不是 Region 層的統一國家表。
- 建國入口只有測試用 `register_trial_equipment_nation`（`site_controller.gd:1448`，限 `trial_team_` 開頭、整隊同 faction）與情境設元首 `appoint_nation_head`（`site_equipment_orders.gd:111`，註明「不是玩家或 AI 路徑」）。
- 地圖編輯器計畫 §9.1 把「faction／nation／聚落 owner_faction／領土」定為四種不同關係，要求國家↔faction 採**明示、可空**映射（第 292 行），並把「正式情境建國」「國家名稱／陣營映射」列為未完成（第 54、284 行）。
- 職位計畫第 284 行：「nation_id 不等於 faction_id……不由國名猜勢力」；第 466 行：叛離首包只能變成無所屬人物，沒有正式接收入口前不能改 `faction_id`。

### 1.5 顯示

UI 直接顯示數字，而且不一致：`site_controller.gd:828`、`:3080`、`:8146` 顯示原值，`:1176`、`:6537`、`:6547` 顯示 `faction_id + 1`。同一個勢力在不同面板可能顯示成「陣營 0」和「陣營 1」。

### 1.6 結論

1. 勢力沒有任何上層紀錄，所以「誰代表勢力」「勢力叫什麼」「勢力還存在嗎」都沒有答案（貿易 Q11 卡在這裡）。
2. 國家是 Site 本地的組織，勢力是遍布所有 Site 的數字；兩者要靠新增欄位才能連起來。
3. 因為隊伍只有整隊一個 faction，**勢力變動只能以「整隊」「整座建物／聚落」「單一 Actor」為單位**；個人換邊要走職位計畫的原人移交，不能改一個欄位了事。

## 2. 設計原則

1. **勢力＝敵我單位，國家＝組織。** 判敵、設施權限只看勢力；任官、配裝、國庫看國家。這沿用現有程式與地圖編輯器 §9.1，不合併兩個概念。
2. **一個 owner。** 勢力名冊只存在 Region Slot，Site 不存副本，只存數字。
3. **數字永不重用。** 勢力消滅、合併後，它的 ID 保留為歷史，不分給新勢力。舊存檔、收據、陷落紀錄裡的數字永遠指向同一個勢力。
4. **沒有名冊就逐位不變。** 舊檔與沒有 Slot 的單獨 Site（TerrainLab、編輯器試玩）視為「每個出現過的數字是一個無名、無首長的勢力」，所有行為與現在相同。
5. **變動是交易。** 合併、分裂一次提交；做不完整就拒絕，不改一半。

## 3. 勢力怎麼分

### 3.1 勢力名冊（Region Slot）

新增版本化 `faction_registry`，每筆：

| 欄位 | 說明 |
| --- | --- |
| `faction_id` | 既有數字，穩定、唯一、不重用 |
| `name`、`color` | 顯示用；改名不改 ID |
| `kind` | `player`（玩家所屬）、`npc`（情境勢力）、`rebel`（遊戲中分裂產生） |
| `leader` | 勢力首長的 PersonRef（Site＋person_id，沿 `organization_refs` 的引用格式）；可空 |
| `nation` | 綁定的國家引用（Site＋nation_id）；可空，見 §3.2 |
| `status` | `active`／`merged`／`extinct` |
| `merged_into` | 合併後指向的勢力；只在 `merged` 時有值 |
| `founded_at`、`ended_at` | 遊戲時刻 |

貿易 §5.5 的 `faction_relations` 放在同一個 Slot 區塊旁邊，用名冊驗證兩端都存在且 `active`。

**領土不存**：一個勢力擁有哪些聚落，由各 Site 的 `settlement.owner_faction` 推導。冷 Site 不載入就看不到，所以 Region 需要一份「每個 Site 的聚落擁有者」摘要，在 Site 提交時更新（推論：目前 Slot 裡沒有找到這份摘要，需新增）。WORLD 層瀏覽勢力時讀這份摘要。

### 3.2 勢力與國家（FQ1）

建議：**一個勢力最多一個國家；正式國家必屬於一個勢力。**

- 國家紀錄新增 `faction_id`（新 schema 必填；舊的 `trial_team_` 測試國可空，沿地圖編輯器「明示可空映射」）。
- 國民原則上屬於該勢力，但允許暫時不同（例如被俘的國民還是本國籍，但人在敵方隊伍）。這和職位計畫第 284 行「nation_id 不等於 faction_id」相容：映射是明示的，不由國名猜。
- 沒有國家的勢力可以存在（土匪、剛分裂的叛軍、遊戲初期的玩家）。

### 3.3 勢力首長（回答貿易 Q11，FQ2）

建議：

- **有國家的勢力：首長就是元首。** 名冊的 `leader` 不另外存，直接由國家 `offices` 的元首位推導，避免兩邊不一致。
- **沒有國家的勢力：** 首長存在名冊 `leader`。玩家勢力的首長是玩家建立的角色；NPC 勢力由情境或地圖編輯器指定。
- **首長權限：** 宣戰、講和、簽通商協定（貿易 T6）、接受歸附、宣布建國。首長須清醒、自由、在世；否則這些操作拒絕，關係維持現狀。
- **繼承（FQ3 已決定：家族接任）：** 有國家時沿職位計畫 R5（指定繼承人→爭奪）。沒有國家時，首長死亡或永久失格後由**首長所屬家族**接任：
  1. 首長本人是家主：先依家族既有的家主接續規則（`site_family_continuity.gd`、職位計畫 §9 家族繼承）產生新家主，新家主同時成為勢力首長。
  2. 首長不是家主：由該家族現任家主接任勢力首長。
  3. 接任者須清醒、自由、在世，且屬於本勢力；不合格就依同一家族接續順位往下找。
  4. 首長沒有家族，或家族裡沒有合格的本勢力成員：勢力首長空缺，關係凍結，直到情境補人或建國。
  5. 家族名冊目前是 Site 本地紀錄（地圖編輯器第 310 行：外地族人只唯讀）。首版只在首長所在 Site 的族人中找接任者；跨 Site 族人接任等家族跨地點引用完成後再開。
  名冊的 `leader` 在接任提交時改寫；接任與家族接續同一次提交，不能只換一邊。

這等於把貿易 Q11 的 A（勢力首長登記）和 B（元首決定）合在一起：建國前用 A，建國後自動變成 B。

### 3.4 Taiwan 第一版開局

- 開局情境檔列出全部勢力（名字、顏色、首長、起始聚落、初始關係），寫入新世界的名冊。勢力數量、名字與分布不在本計畫處理（FQ9 已移出，另案）；本文只定名冊格式，情境給幾個就登記幾個。
- 玩家角色建立時，**新開一個只有玩家的勢力**（FQ8 已決定 A），首長＝玩家角色，跟所有情境勢力預設敵對；也可以在主選單選擇加入某個情境勢力。
- 情境裡的數字從 0 開始連號；新勢力用「目前最大值＋1」。

## 4. 勢力怎麼變

下表是全部會改變勢力的事件。每一種都只動名冊加上**整單位**的 faction 改寫（整隊、整座建物、整座聚落、單一 Actor）。

| 事件 | 觸發 | 結果 | 首版 |
| --- | --- | --- | --- |
| 開局建立 | 情境／地圖編輯器 | 名冊新增 | F1 |
| 玩家建立勢力 | 新遊戲建立角色 | 名冊新增 `player` 勢力 | F1 |
| 建國 | 勢力首長宣布（§4.1） | 新增國家並綁定 | F3 |
| 聚落陷落 | 現有 `fall_to` | 不改名冊，只改聚落與建物擁有者（現行） | 已有 |
| 歸附（合併） | 兩方首長同意（§4.2） | 弱方 `merged`，全部單位改成強方 | F4 |
| 消滅 | 自動判定（§4.3） | `extinct` | F4 |
| 分裂／自立 | 隊長或聚落首長叛離（§4.4） | 名冊新增 `rebel` 勢力 | F5 |
| 個人投奔 | 職位計畫 §10 | 單一人物移到目的勢力的隊伍或成為 Actor | 職位計畫負責 |

### 4.1 建國（FQ4）

建議條件：

1. 勢力 `active`，還沒有國家。
2. 首長清醒、自由，人在本勢力擁有的已建制聚落。
3. 本勢力至少擁有一座 **2 級以上**聚落（聚落中心計畫的等級）。

結果：在首長所在 Site 用正式入口（取代 `register_trial_equipment_nation`）建立國家紀錄，`faction_id` 設為本勢力；首長成為元首；國民先只有首長，其他人由國家 `nation.admission`（職位計畫戶籍官）之後納入，**不一鍵把整個勢力的人都改國籍**。聚落的 `nation_id`（地圖編輯器 §9.2 計畫新增）由首長明示指定。

### 4.2 歸附（合併，FQ5）

- 只能由兩方首長同意：弱方首長提出、強方首長接受。NPC 首版只在「弱方已失去全部聚落，或兵力不到對方十分之一」時提出（推論的簡單門檻，可改）。
- 前提：兩勢力之間沒有進行中的戰鬥（沿貿易 §5.5 講和前提）。
- 提交：名冊上弱方 `merged`、`merged_into`＝強方；弱方的關係表項目刪除；弱方國家（若有）解散，國民變無國籍，之後由強方國家個別收編。
- **冷 Site 不立刻改寫。** 已載入 Site 在同一提交裡把弱方的隊伍、Actor、建物、聚落 faction 改成強方；未載入的 Site 在下次 bind 時，先依名冊 `merged_into` 把舊數字換成新數字，再進入既有驗證。這樣一次合併不用同時打開全部 Site。

### 4.3 消滅

勢力在全部 Site 都沒有活人、沒有建物、沒有聚落時標為 `extinct`，關係表項目刪除。判定在 Site 提交時用 Region 摘要做，不額外掃描冷 Site。只剩俘虜（被別方拘押）的勢力不算消滅，可以被贖回後復起。

### 4.4 分裂與自立（FQ6）

- **隊伍自立**：一支隊伍的正式隊長叛離時，整隊（含車輛、隨隊物資）改成一個新 `rebel` 勢力，隊長是首長。不願跟隨的隊員依職位計畫 §10 退隊，留在原勢力。
- **聚落自立**：聚落首長叛離時，聚落中心與管轄內原屬本勢力的建物改成新勢力（沿用 `fall_to` 的建物換手規則，但不清空職位）；駐守隊伍各自選邊。
- 叛離的條件、門檻、預兆、支持者名單全部沿職位計畫 §8.4／§10.2，本文只補「目的勢力可以是新建的勢力」這一個出口。
- 新勢力與原勢力預設敵對；與其他勢力的關係沿用「未登記＝敵對」。

### 4.5 不做的事

- 不讓一個人在隊伍裡單獨換邊（Army rows 沒有逐人 faction）。
- 不做「附庸」「同盟」這類多層關係；首版只有 peace／hostile（貿易 §5.5）和合併。
- 不做勢力之間的領土談判、割讓聚落。

## 8. 驗收

- **FA-01 舊檔不變**：沒有名冊的舊世界開啟後，全部既有戰鬥、Crowd、出發守衛、Region 到站、聚落陷落測試結果逐位不變；名冊只多出無名條目。
- **FA-02 顯示一致**：同一勢力在全部面板顯示同一名字與顏色；沒有名冊時顯示同一數字。
- **FA-03 ID 不重用**：勢力合併或消滅後再建立新勢力，新 ID 大於歷史最大值。
- **FA-04 首長**：有國家時首長＝元首，元首換人後立即生效；沒有國家時首長死亡由家族接任（家主本人死亡時新家主接任；非家主時現任家主接任；無合格族人則空缺凍結），接任與家族接續同一次提交；首長昏迷、被俘、死亡時宣戰、講和、建國、歸附全部拒絕。
- **FA-05 建國**：不滿足 §4.1 任一條件拒絕；成功後只有首長成為國民，其他人國籍不變。
- **FA-06 歸附**：已載入 Site 的弱方單位同一提交改成強方；未載入 Site 在下次 bind 時改寫且驗證通過；兩勢力仍在交戰時拒絕；有 Crowd 的 Site 未支援時拒絕且不改一半。
- **FA-07 消滅**：只剩俘虜不算消滅；全部人、建物、聚落都沒了才 `extinct`。
- **FA-08 分裂**：隊伍自立後整隊同一新勢力，不跟隨者已退隊；聚落自立後建物換手規則與 `fall_to` 一致但職位保留。
- **FA-09 存讀**：名冊、關係、別名改寫後存讀與 Region 共同 checkpoint 一致。
- **FA-10 書信送達**：提議在送達時刻前對方看不到、不能回覆；送達時刻依兩首長所在 Site 的 Region 距離計算，暫停、慢幀、存讀不改變送達時刻，也不重複送達。
- **FA-11 提交前重驗**：接受時重驗雙方首長合格、勢力仍 `active`、提議未過期、前提（例如沒有進行中戰鬥）仍成立；任一失效則提議作廢，關係不變。
- **FA-12 同對同類只一件**：同一對勢力同一種提議只能有一件待回覆；被拒後冷卻期內再提被拒。
- **FA-13 停戰到期**：停戰期間雙方不互打（走 `hostile()` 單一入口）；到期未講和自動回到敵對，進行中的交易依貿易 §5.5 宣戰規則收束。
- **FA-14 宣戰與背約**：對有效停戰或通商協定的對象宣戰，協定同次作廢並寫入背約紀錄；全部勢力都看得到這筆紀錄。
- **FA-15 NPC 規則**：NPC 首長只依 §11.6 的規則與公式提議、回覆、宣戰；野心、仁厚只在 §11.6 列出的讀取點使用，其他人格軸不讀；`duty_ai` 關閉時不主動提議或宣戰但仍回覆；受控首長從不被 AI 代為決定。人格邊界值（0、50、100 與公式門檻等號）各驗一次。
- **FA-16 冷 Site 首長**：首長所在 Site 未載入時，NPC 外交決策只讀 Region 摘要與名冊，不載入或改寫任何 Site；結果與首長所在 Site 載入時相同輸入下一致。
- **FA-18 收復宣戰**：只有「對方占著本勢力陷落紀錄中的聚落」才會觸發 NPC 主動宣戰；野心與仁厚未達 §11.6 門檻、兵力不足或在簽約冷卻內時不宣戰；宣戰對和平對象同時寫入背約紀錄。
- **FA-19 背約不滿**：背約提交時，背約方國家每位有社會狀態的國民（首長本人除外）不滿 +5 一次，以背約紀錄 ID 去重；與其他正向事件合計仍受當日上限 20；沒有國家或職位計畫 R2 尚未上線時只留紀錄，不補算。
- **FA-17 合併與消滅**：勢力合併或消滅時，它的待回覆提議全部作廢、協定全部終止，不留下指向非 `active` 勢力的紀錄。

## 11. 外交

### 11.1 現有基礎與缺口

目前和外交有關、已經寫下的只有：貿易規劃 §5.5 的 `peace`／`hostile` 關係表與宣戰、講和規則；貿易 T6 的通商協定；職位計畫的俘虜贖回；本文 §4.2 的歸附合併。沒有定義的是：提議怎麼送達、協定有哪些、NPC 什麼時候提議或接受、違約的後果。貿易規劃提到的「外交主線」並不存在，本章就是它。

本章不改 §2 的原則：判敵仍只經 `SiteFactionRelations.hostile(a, b)` 一個入口，「同一方」權限不因任何協定放寬。

### 11.2 外交狀態與協定（FQ11 已決定 A）

**關係**（存在 `faction_relations`，判敵只看這個）：

| 關係 | 意思 |
| --- | --- |
| `hostile` | 敵對，現有互打規則。未登記＝敵對 |
| `peace` | 和平，不互打，可交易（貿易 §5.5） |

**協定**（存在新的 `diplomacy.treaties`，疊在關係上面）：

| 協定 | 效果 | 期限 |
| --- | --- | --- |
| 停戰 | 簽署時關係改為 `peace`，到期時若未改簽講和，自動回到 `hostile` | 必填，3–60 遊戲日 |
| 講和 | 關係改為 `peace`，沒有期限 | 無 |
| 通商 | 貿易 T6：商隊可入對方聚落、稅率；前提是關係為 `peace` | 選填 |
| 歸附 | §4.2 合併，提交後協定即完成 | 無 |

停戰和講和的差別只在有沒有期限，所以判敵程式不需要知道「停戰」這個概念。

### 11.3 提議怎麼送到對方（FQ10 已決定 A）

採用**書信**：

- 提議是 Region Slot 裡的一筆紀錄：`id`、發出方、接收方、種類、條款、發出時刻、送達時刻、回覆期限、狀態。
- 送達時刻＝發出時刻＋兩位首長所在 Site 在 Region 上的距離 ÷ 騎馬速度（沿 `region_travel.gd:717` `party_speed` 的車輛速度表；推論，數值可調）。同一 Site 視為立即送達。
- 送達前對方看不到；送達後對方有 7 遊戲日可回覆，逾期作廢。
- 回覆（接受、拒絕）同樣以書信延遲送回；**接受的效力在回覆送達發出方時才提交**，提交前重驗全部條件（FA-11）。
- 同一對勢力同一種提議同時只能有一件；被拒後 3 遊戲日內不能再提同一種。

宣戰不是提議，見 §11.5。

### 11.4 提議流程

1. 首長（§3.3）選對象、種類與條款，預檢：自己合格、對方 `active`、該種協定的前提（例如講和要求兩勢力之間沒有進行中的戰鬥，沿貿易 §5.5）。
2. 寫入提議紀錄，計算送達時刻。
3. 送達後由對方首長決定：受控首長在面板明示；NPC 首長依 §11.6。
4. 接受的回覆送達後一次提交：寫協定、改關係、通知雙方。任一前提失效則作廢，關係不變，雙方收到原因。
5. 合併、消滅、首長空缺時，相關待回覆提議全部作廢（FA-17）。首長換人不使提議作廢，由新首長決定。

### 11.5 宣戰與背約

- 宣戰由首長單方決定，**立即生效**（沿貿易 §5.5），不經書信延遲；對方在下一次 Region 更新時收到通知。
- **背約＝對關係為 `peace` 的勢力宣戰**，不論雙方之間是停戰、講和還是通商。停戰自然到期回到敵對不算背約。背約時該對勢力的全部協定同次作廢，寫入背約紀錄（背約方、受害方、作廢的協定、時刻），全部勢力都看得到。

  V0.3 只把「對有停戰或通商協定的對象宣戰」算背約；但講和本身也是協定，打破它不算背約說不通，V0.4 改為上面的定義。也因此，「對方對自己背約」時雙方已經自動進入戰爭，FQ13 A 的這一項不需要另外宣戰，改為由受害方拒絕講和來表現（下一點）。

- **背約後果（FQ14：A 與 B 都採用）：**
  - **A. 拒絕提議。** 受害方 30 遊戲日內拒絕背約方的任何提議；其他 NPC 勢力 10 遊戲日內拒絕。受控首長不受限制，只會看到紀錄。
  - **B. 本國不滿。** 背約方若有國家，提交背約時，國家每位有社會狀態的國民（首長本人除外）不滿 G +5 一次。責任來源是背約的首長，以背約紀錄 ID 去重，與其他正向事件合計仍受職位計畫 §8.1 的當日上限 20。沒有國家的勢力、或職位計畫 R2 社會狀態尚未上線時，只留紀錄，事後不補算。數值 +5 比照「被免職 +10」減半，可調。

### 11.6 NPC 首長的外交規則

`duty_ai` 關閉時不主動提議或宣戰，但仍依同規則回覆（沿貿易 TR-33）。

**決策時機**（FQ15 已決定 A）：每遊戲日一次，在 Region 層執行，只讀名冊、`faction_relations`、`diplomacy` 紀錄、§3.1 的 Region 摘要，以及首長人物的人格值，不載入或改寫任何 Site。首長人格值在首長所在 Site 提交時抄進名冊摘要；這是只讀副本，人格的唯一 owner 仍是原人物。

**兵力**：一個勢力的兵力＝ Region 摘要中該勢力成年可戰原人物數（推論：目前摘要沒有這個值，需在 Site 提交時一併更新）。下表的「兵力比」＝自己兵力 ÷ 對方兵力。NPC 只用摘要值，不讀冷 Site 真值。

**人格讀取（FQ12 已決定 B）：** 只讀首長的**野心 A** 與**仁厚 M**（0–100，50 中性）。這是 Nekki 2026-10-08 明示同意的外交專用讀取點，不讀其他軸；同一條決策中每軸只用一次。

| 決策 | 規則 | 中性（A=M=50）時 |
| --- | --- | --- |
| 回覆講和、停戰 | 接受，若同時：① 對方不在背約冷卻內；② 兩勢力已連續 `D = 3 × (1.5 − M/100)` 遊戲日沒有交戰（M=100 為 1.5 日、M=0 為 4.5 日）；③ 兵力比 < `3 − 2 × A/100`（野心高的人占上風時不肯和；A=100 時只要不輸就拒絕，A=0 時要贏到三倍才拒絕） | 3 日沒交戰，且兵力比 < 2 |
| 回覆通商 | 接受，若關係為 `peace`、對方不在背約冷卻內，且稅率不高於自己對同類協定的稅率；不讀人格 | 同左 |
| 回覆歸附 | 接受；對方在背約冷卻內則拒絕；不讀人格 | 同左 |
| 主動求和 | 與某敵對勢力交戰中，且兵力比 < `0.5 + (M − A)/200`（範圍 0–1）：提停戰 15 遊戲日；停戰期滿前 3 日提講和 | 兵力比 < 0.5 |
| 主動提歸附 | 自己失去全部聚落，或兵力比 < 0.1（§4.2）；不讀人格 | 同左 |
| 主動宣戰（收復，FQ13） | 只在「對方占著本勢力陷落紀錄中的聚落」時考慮，且同時：① `A − M ≥ 0`（野心不低於仁厚才願意打破和平）；② 兵力比 ≥ `1.5 − A/100`（A=100 時半數也敢打，A=0 時要 1.5 倍）；③ 與對方簽約滿 10 遊戲日 | 願意，兵力比 ≥ 1 且簽約滿 10 日 |

- 收復宣戰的對象關係必為 `peace`（敵對時本來就在打），所以一定同時構成背約，§11.5 的兩項後果都照常發生；NPC 在決定時已把這點算進門檻 ①。
- 除了收復，NPC 不主動宣戰（FQ13 A）。
- 宣戰之後是否真的派兵，由既有的派遣職責（`region_gameplay_ai.gd:122`，`nation.dispatch`）決定；外交規則不直接移動任何隊伍。
- 公式中的常數（3、15、10、0.1 等）是首版數值，之後可調，但改動要同步驗收 FA-15 的邊界案例。

### 11.7 玩家的外交

- 玩家是自己勢力的首長時，WORLD 層勢力面板（§6）提供：查看每個勢力的關係、協定、背約紀錄；發出提議；查看收到的提議並回覆；宣戰。
- 收到提議、提議被接受或拒絕、停戰快到期、被宣戰時發通知。
- 玩家不是首長（例如加入了情境勢力當一般成員）時只能看，不能操作。
- AI 從不替受控首長決定任何外交事項。
