## 0. 一句話結論

程式裡**已經有半套天氣**：火攻系統完整支援風向、降雨與乾燥，只是目前只有測試視窗能設定，沒有任何東西會自動產生天氣。晝夜與季節則完全沒有。

建議的做法是加一個很薄的「環境服務」：**天氣由世界種子與日期直接算出來，不存檔**，所以沒載入的 Site 不用補算天氣，讀檔也不會改變天氣。先做畫面與顯示，再把算出來的風雨接到火攻，之後才逐步加上農作、行軍、航海與戰鬥的效果。每一期都能單獨停下來。

## 2. 三個會決定設計方向的事實

**事實一　經濟是壓縮過的。**
農田 8 小時收一次，一年 360 日可以收一千多次。所以季節不能做成「春耕秋收」的真實農曆，除非把整個糧食經濟重新平衡。季節比較適合當成**倍率**，疊在現有週期上。

**事實二　時間流速差很多。**
戰鬥中是 1 比 1，一場十分鐘的仗裡天氣幾乎不會變，晝夜也不會變。和平時一天 24 真實分鐘，大地圖一天 2.4 分鐘，等待時更快。所以天氣對戰鬥來說是「開打時的條件」，對經濟來說是「長期平均」，這兩種效果要分開設計。

**事實三　沒載入的 Site 是事後補算的。**
冷 Site 回來時每 8 遊戲秒一步重播。如果天氣是隨機抽出來再存檔，每張 Site 都要存一份歷史，補算時還要對齊。如果天氣是「種子＋日期」的純函式，任何 Site 在任何時刻都能直接問，不必存也不必補。

## 3. 設計原則

1. **天氣算得出來，不用存。** 同一個存檔、同一天、同一個 Region，天氣永遠一樣。
2. **先畫面，後規則。** 每一期都可以單獨上線，也可以停在那一期不往下做。
3. **沿用現有機制。** 風雨接火攻現成的輸入，休息接疲勞現成的倍率，居民避雨接已定案的避難流程，水接現成的供水比例。
4. **效果要小而清楚。** 倍率集中在一張表，玩家在畫面上看得到原因（例如時鐘旁顯示「大雨：遠程命中下降」）。
5. **舊測試不受影響。** 測試場景預設「環境關閉」，等同現在的固定晴天白晝。只有新開局才打開。

## 4. 設計方案

### 4.1 環境服務（一個純函式模組）

新增 `SiteClimate`（名稱暫定），只有查詢，沒有自己的時鐘：

```
SiteClimate.at(world_seed, region_id, site_altitude, game_seconds) -> {
  band:    dawn | day | dusk | night        // 時段
  light:   Color                            // 全畫面調色
  season:  spring | summer | autumn | winter
  weather: clear | cloudy | drizzle | rain | storm | fog
  rain:    0.0–1.0                          // 直接給火攻用
  wind:    Vector2（長度 ≤ 1）              // 直接給火攻與船用
  drying:  0.0–0.02                         // 直接給火攻用
}
```

- 存檔只多兩個欄位：`climate_enabled` 與版本號。舊存檔讀進來是關閉，行為和現在一樣。
- 測試視窗的「火場天氣」保留，改成「覆寫」：有覆寫時用覆寫值，方便測試固定條件。

### 4.2 晝夜

| 時段 | 時間 | 畫面 |
|---|---|---|
| 黎明 | 05:00–07:00 | 由深藍漸變到暖白 |
| 白天 | 07:00–17:00 | 現在的樣子 |
| 黃昏 | 17:00–19:00 | 漸變到橙紅再到深藍 |
| 夜晚 | 19:00–05:00 | 深藍，亮度約白天的 45%，仍看得清單位 |

- 日出 06:00、日落 18:00。和 T8 的 06:00 開局一致，開場是日出。
- 和居民日程對得上：居民 05:00 起床時天剛亮，18:00 收工時是黃昏，22:00 睡覺時已是深夜。
- 做法：Site 與大地圖各加一個全畫面調色節點（`CanvasModulate`），UI 不受影響。人物圖集不用重烘。
- 夜間的火把、營火、燃燒中的建築用疊加的光暈圖，不用即時 2D 光源（幾千人的場面下即時光源成本不明，見 §7 風險二）。
- 夜晚亮度刻意不壓太低。這是指揮幾千人的遊戲，看不清楚比不夠寫實更糟。

### 4.3 季節

沿用 T3 的曆法：1–3 月春、4–6 月夏、7–9 月秋、10–12 月冬，每季 90 日。

第一版只顯示（和 T4 的建議相同）。之後的效果全部是倍率，疊在現有週期上：

| 項目 | 春 | 夏 | 秋 | 冬 | 掛在哪裡 |
|---|---|---|---|---|---|
| 農田產量 | 1.0 | 1.2 | 1.1 | 0.6 | `productivity`（現有） |
| 牧草／放牧容量 | 1.0 | 1.1 | 1.0 | 0.7 | `grazing_capacity` |
| 野生食物、藥材恢復 | 1.2 | 1.0 | 1.2 | 0.5 | `RECOVERY` 的倍率 |
| 魚 | 1.0 | 1.0 | 1.0 | 0.8 | 同上 |
| 農田需水量 | 1.0 | 1.3 | 1.0 | 0.7 | `water_demand` |

- 全年平均產量大約和現在一樣（0.975），所以不用重調糧食數值，但冬天要靠存糧。這會讓糧倉、存糧上限與稅的時間點變得有意義。
- 冬天不做「凍死」「柴火」之類的新需求，第一版只有產量變化。
- 地表顏色隨季節微調（夏天綠、冬天偏黃），用同一個調色節點處理，不換貼圖。

### 4.4 天氣

**一個 Region 一種天氣**，每 2 遊戲小時一個時段（和平時約 2 真實分鐘換一次，戰鬥中等於不變）。

| 天氣 | 降雨 | 風 | 乾燥 | 畫面 |
|---|---|---|---|---|
| 晴 | 0 | 弱 | 0.02 | 現狀 |
| 陰 | 0 | 弱–中 | 0.01 | 稍暗、偏灰 |
| 小雨 | 0.3 | 弱–中 | 0 | 細雨線 |
| 大雨 | 0.7 | 中 | 0 | 密雨線、更暗 |
| 暴風雨（颱風） | 1.0 | 強 | 0 | 斜雨、畫面最暗 |
| 霧 | 0 | 無 | 0.005 | 淡白霧，只在清晨 |

- 產生方式：每天先由種子抽「今天的型態」（依季節的機率表），再把一天分成 12 個時段排出變化，相鄰兩天有連續性（雨天多半連著下）。
- 風向：每季有盛行風向（見 4.5），每天在盛行風向附近擺動。
- 高山 Site 的降雨機率略高、溫度帶偏冷一級，用 Site 的海拔修正，不另外模擬。
- 畫面：雨是一層全畫面的著色器加一個調色，不逐格畫。
- 聲音：雨聲、風聲、雷聲由同一個查詢驅動，補上音效計畫缺的權威來源。

### 4.5 氣候表（跟著地圖走）

目前的地圖是台灣與周圍海域，所以第一張氣候表建議做成亞熱帶季風型，表是資料，之後擴到其他 Region 只要換表：

| 季 | 月 | 特徵 | 盛行風 |
|---|---|---|---|
| 春 | 1–3 | 多陰與小雨，季末進入梅雨 | 東北轉弱 |
| 夏 | 4–6 | 4 月梅雨（連日大雨），之後晴熱、午後雷陣雨 | 西南 |
| 秋 | 7–9 | 颱風季：每年 2–4 次暴風雨，每次 1–2 日 | 西南轉東北 |
| 冬 | 10–12 | 東北季風：風強、北部多小雨、南部乾 | 東北 |

平地不下雪。海拔很高的 Site 冬天畫面可以偏白，但不做積雪規則。

### 4.6 接到火攻（現成的）

- 每當時段切換，把查到的風、雨、乾燥寫進 `fire_set_weather`，火攻的潮濕、引燃、延燒與煙就會自動跟著天氣走，不用改火攻規則。
- 效果：雨天火攻很難點起來，強風天延燒很快而且有方向，連續晴天之後草木乾燥最容易起火。這是這套系統第一個有戰術意義的地方，而且幾乎不用寫新規則。
- 要處理的技術細節見 §7 風險一（歷史上限 4096 筆、時間單位換算）。

### 4.7 其他系統的效果（分期加入，全部是小倍率）

| 系統 | 效果 | 掛在哪裡 |
|---|---|---|
| 居民 | 大雨與暴風雨時停止戶外工作並回家，走已定案的避難流程（不算戰鬥）；小雨照常 | 居民日程的參數 |
| 疲勞 | 雨中或夜間露天休息恢復 ×0.7；在營帳或屋內不受影響 | `recovery_multiplier`（現成） |
| 大地圖行進 | 小雨 ×0.9、大雨 ×0.75、暴風雨 ×0.5；夜間 ×0.85；道路上的懲罰減半 | `speed_multiplier` |
| 航海 | 帆船順風最多 +25%、逆風最多 −40%；槳船受影響減半；暴風雨不能出港，已在海上的船速 ×0.5 並有受損機會 | `Ship.speed` |
| 遠程 | 小雨 −5、大雨 −15、暴風雨 −30；夜間 −10（目標旁有火光則不扣）；強風再 −5 | `fire_aim_offset` 的 `quality` |
| 近戰 | 不受影響（維持單純） | — |
| 農田供水 | 下雨的時段，露天農田視為有額外供水；連續 10 日無雨時水井與取水口的供水量 ×0.7（乾旱） | `water_status` |
| 視野與偵察 | 夜間與霧天，大地圖上發現對方隊伍的距離縮短，情報回條的準確度下降 | 大地圖 intel |
| NPC | NPC 知道天氣：雨天不發動火攻、暴風雨不出海。夜襲是否開放見 D7 | NPC AI 的硬否決輸入 |
| 士氣／不滿 | 天氣不直接加不滿。只透過歉收、斷糧、房屋受損間接影響 | `SiteSocial`（不改） |

### 4.8 預報

- 時鐘旁顯示目前的季節、時段與天氣圖示。
- 任何人都能看到「今天接下來」的大概天氣。
- 聚落有虞衡（`settlement.ecology`）任職時，可以看到未來 3 日的預報。這讓虞衡這個職位多一個實際用途，也給玩家安排火攻、出海與收成的依據。

## 5. 已決定的事（D1–D10 全選 A，2026-11-15 定案）

**D1　天氣的範圍**
- **A（建議）一個 Region 一種天氣**（20×20 公里），高山 Site 再用海拔修正。簡單、畫面與大地圖一致、相鄰 Site 不會一晴一雨。
- B　每張 Site 各自的天氣。比較細，但 200 公尺一格的天氣差異不合理，資料量也大。
- C　全世界同一種天氣。最簡單，但跨 Region 之後不合理。

**D2　天氣怎麼產生**
- **A（建議）由種子與日期算出來，不存檔。** 冷 Site 不用補算，讀檔不能刷天氣，測試可以重現。
- B　隨機抽、存進存檔。可以做出「真的不可預測」，但每張 Site 都要保存與補算歷史。

**D3　氣候類型**
- **A（建議）亞熱帶季風型**（梅雨、颱風、東北季風，平地不下雪），配合現在的台灣地圖；氣候表做成資料，別的 Region 可以換。
- B　通用的溫帶四季（冬天下雪、河面結冰）。畫面變化大，但和地圖不符，結冰還要改水域通行規則。

**D4　晝夜長短**
- **A（建議）全年固定 06:00 日出、18:00 日落。** 和居民日程、06:00 開局都對得上，規則簡單。
- B　隨季節變化（夏天晝長、冬天晝短）。比較真實，但居民日程與夜間規則都要跟著浮動。

**D5　季節怎麼影響農作**
- **A（建議）倍率**：維持 8 小時一收，季節只調產量（冬 0.6、夏 1.2，全年平均不變）。不用重調糧食數值。
- B　真實農曆：春天播種、秋天收成，一年一到兩收。很有味道，但整個糧食、稅、人口數值都要重做，已定案的薪餉與稅規劃也要跟著改。

**D6　天氣對戰鬥的影響**
- **A（建議）只影響遠程與火攻**（遠程命中下降、雨天難起火、風向決定延燒），近戰與移動不受影響。
- B　也影響近戰與陣形移動（泥濘減速、雨中體力消耗加快）。會動到剛完成的 crowd 戰鬥調校與大量回歸測試。
- C　天氣完全不影響戰鬥，只影響火攻。

**D7　夜晚對規則的影響**（延伸 game-time T6）
- **A（建議）分兩步**：先只做畫面（等同 T6 的 A）；戰鬥期再加上夜間遠程命中下降、大地圖偵察距離縮短、露天休息變差，並開放 NPC 夜襲。士兵不強制睡覺。
- B　永遠只做畫面。
- C　全面模擬：所有人都要睡覺，不睡會累積疲勞。會改到每一支隊伍的日常，範圍很大。

**D8　風對航海的影響**
- **A（建議）要做，但排在最後**：帆船受風向影響，暴風雨不能出港。等接舷 B5 完成後再動船速，避免兩邊同時改船。
- B　風只影響火攻，船不受影響。

**D9　災害**
- **A（建議）只做颱風與乾旱，放在最後一期**：颱風有 1 日預兆、損壞未完工的建築與露天存放的物資、船不能出海；乾旱讓供水下降。不做洪水、瘟疫、蝗災。

## 7. 風險與要先量的東西

**風險一　火攻天氣歷史有上限。**
`weather_history_cap` 是 4096 筆。每 2 小時寫一筆的話，一張一直開著的 Site 大約 341 遊戲日就會寫滿。要先加「把已經沒有物件需要的舊歷史合併掉」的整理，或改成火攻直接查純函式。另外火攻歷史用的是動作時間（真實秒累計），天氣用的是遊戲時間，寫入時要換算。這兩點是 S2 的主要工作量。

**風險二　夜間光源的成本。**
全畫面調色幾乎沒有成本，但如果火把用即時 2D 光源，在 5000 人場面下的成本沒有量過。所以建議先用疊加光暈圖，S1 開工時量一次。

**風險三　冷 Site 補算。**
季節倍率與下雨補水會進入冷 Site 的重播。因為天氣是純函式，補算結果是確定的，但每一步多一次查詢。查詢要按時段快取（一個時段只算一次）。

**風險四　存糧壓力。**
冬季產量 0.6 之後，沒有存糧的聚落會在冬天斷糧。NPC 聚落要會在秋天多存糧，否則會出現整片 NPC 聚落冬天餓死的情況。S3 要包含這個 NPC 行為與一個 360 日的長跑測試。

**風險五　玩家感受。**
和平時一天 24 分鐘，夜晚佔 10 小時就是 10 真實分鐘的暗畫面。所以夜晚亮度不能壓太低，而且「原地等待到天亮」（game-time T1）最好和 S1 一起上線。
