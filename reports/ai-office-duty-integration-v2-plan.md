## 3. 官職是真值 幹部是投影

### 3.1 文官與武官

在原 `SiteOffices` 版本化職位上新增 `office_class = civil | military`。它是官職分類，不是新的 `military_role` 或人物類型。

〔審核補，實作前提〕目前 `SiteOffices.validate` 嚴格要求 offices 恰好六鍵、`version == 1`、每個職位恰好四鍵（id／name／head／holder）。新增 `office_class` 必須把 `SiteOffices.VERSION` 升為 2，舊 v1 紀錄讀入時一次遷移（依第 3.1 表的固定分類映射補值），validator 同時接受 v1 讀入、只寫出 v2；隊伍、國家、家族、聚落四處 offices 都走同一遷移。新增職責（`team.recruit`、`nation.admission`、`nation.ransom`）沿用職位計畫 3.2 與現有 `SiteOffices.LATER_DUTIES`：舊紀錄缺少時自動補一個空缺職位、由首長代行。目前 `LATER_DUTIES` 只登錄隊伍三項與聚落典獄，國家尚未登錄，加國家職責時須同時登錄，否則舊國家存檔會被拒絕載入。名稱可為「文官」「武官」，也可改成書記、工務官、教官等；判定看分類與職責，不看文字名稱。

| 一般官職 | 首包簡單職責 | 執行來源與限制 |
|---|---|---|
| 文官 | 生產調度 | 沿 `team.work` → 原 `SiteWorkTeam.assign`、`work_task`、Runtime 付料／完工；不另建同權限的 `team.production` |
| 文官 | 名冊與人員調整 | 沿 `team.roster`；來源與接收同意、停止、供養等守衛保留 |
| 武官 | 訓練 | 沿 `team.training`、原校場與共用訓練時鐘 |
| 武官 | 募兵 | 新 `team.recruit`：把既有自由原人物或駐營原兵員正式編入；不是造新兵 |
| 武官 | 後勤或器械 | 已接 `team.logistics`；器械職責待逐入口從船務／搜刮釐清後接，不能掛名先授權 |

隊長首長官職為 `military`；家主、國家元首及聚落首長的組織調整權不因分類而放寬。其他既有職位按實際 duty 制定固定分類映射；含募兵、訓練、作戰者須 military，生產／名冊可由 civil 執行，其餘後勤／配裝／典獄兩類均可。

各組織仍同一人最多一官職、每個實際職責恰一 owner。可新增多個文官／武官職位，但不能複製同一職責讓多人共管；在任名額受可分配真職責數約束。多名工人是原工作者，不能為了給官職而把每位工人都變成官員。

### 3.2 任官到幹部的單向關係

1. 先驗候選是該組織的真成員、官職分類與職責相容、本人有該職責所需資格。
2. civil 任命可使用原 civilian／soldier，不自動改成 military officer。
3. military 官職所需軍官資格沿原 `military_role`；需要晉任時同方案走原資格入口，禁止只改字典跳過兵種與裝備守衛。
4. 官職最終方案通過後，隊內非首長在任官職產生 `officer_service` 幹部投影。
5. `officer_order` 是其中合格在任武官的接任子集（2026-10-07 修訂：含具軍官資格的文官在任者），保留原任職先後與玩家明示順位；不再要求與 service 完全相同。
6. 沒有目標隊官職的人不能是該隊幹部。國家或家族官職不自動授予所有隊伍軍權；派駐須有目標隊真官職及其職責。

接任順位仍只由在場正式隊長調整，代理不能代排；任官與組織制度調整沿首長不可委派的原規則，僅永久空缺就任採第3.3／9節的明示例外。

非首長任職以 `offices` 為唯一真值；隊長仍以原 Army 的 `formal_commander` 為真值，head 由它派生，保存的 head holder 沿原 `-1` 標記，不雙寫另一位隊長。收斂 `record_officer_service` 為任官交易的內部投影更新；`_sync_officer_order` 不得從舊順位反補無官職幹部。任官不得先要求已有 service，解除現在的循環。

兵種豁免與接任分開：沿 `PROJECT_ARCHITECTURE` 的「隊長及現任幹部豁免」，原 `_troop_exempt_ids` 改讀正式隊長＋service，包含合法在任文官；不再讀武官順位當全體幹部。Store、拆併、駐營、換裝須得到同一豁免集合；軍令與披風仍另驗原軍官資格，文官豁免不自動取得它們。

職責執行資格與軍事指揮資格分開：派工、名冊等入口驗當前 `resolve` 與原工作／名冊條件；軍令、代理、戰術能力加總另驗在任武官與原 officer 資格。不得為讓文官通過 `command_eligible` 而自動晉軍官。

〔修訂 2026-10-07，使用者：「文官也可以帶兵」〕文官／武官只是職位標籤，以及新職位的預設分類，不再限制帶兵。指揮資格為正式隊長，加上擔任任一非首長職位（文官或武官）且具原軍官資格（`military_role == officer`）者：可代理、接任，計入戰術、`command_effect`、教練與統御加總，也可負責訓練與軍團編成。士兵或平民擔任文官職位仍沒有指揮權，也不自動晉升為軍官（本節上一段仍適用）。訓練與軍團編成職責可以放在文官職位上，但任職者必須具軍官資格。具軍官資格的文官在任者也列入接任順位，並沿用原披風規則（隊長＋接任順位）。文官在任者可以降為士兵並保留文官職位，只是失去指揮權；負責訓練或軍團編成者、武官職位任職者不能降級。自動任命仍只排入空缺的武官職位。

`SiteDutyAI.review_team_personnel` 一併改讀「未任職的真成員＋該職責／分類資格」，不再從 service 找未就座者，因為新 service 恰是已任職者。併責只選分類與資格相容的在任者、沿原每人最多兩項；無合法人選就由首長代行／等待，不把訓練併給不合格文官。

能力公式本身不改，但有官職才取得相應軍事資格後，有效能力集合可能改變；這是新任官規則的可見差異，需明列回歸，不能宣稱所有舊戰鬥數值逐位不變。

〔審核：已定案，使用者 2026-10-07 決定卡〕R1a 與 R1b 都做：代理、接任候選與戰術能力／`command_effect` 加總只計在任武官，接受戰鬥數值改變，並把部分作戰指揮規則提前於原 P4。施工順序 F07→F04→F09→R1a→R1b；R1b 須保留舊存檔可讀，並以固定名冊列出改前／改後加總。以下為原審核說明，保留作紀錄：職位計畫第 7 節（10/6 定案）寫明「`command_effect` 不變，職位不改任何戰鬥、訓練或速度數值」，作戰指揮調動也定為 P4 另案。本節讓「代理、接任、戰術能力加總」改為只計在任武官，會直接改變 `command_effect` 的加總對象與代理人選，屬於戰鬥數值與指揮規則的變更。「有官職才能當幹部」的決定是否包含這個後果，須由使用者明示確認；未確認前，R1 只做不影響 `command_effect`、`command_eligible` 與代理規則的部分（見第 12 節 R1a／R1b 拆分）。

### 3.3 隊長空缺與啟動

原正式隊長／代理／現任指揮者仍由 Army 持有，首長職位是同一人的投影。暫時昏迷、被俘、不在場只走原代理規則，不改正式首長、不開永久空缺入口。

永久空缺時先沿合法武官順位接任。沒有合格在任武官時，先沿原停隊／脫戰條件安全收束原令，再由本隊受控成員提交「空缺隊長就任」；候選須是原同勢力、同 Site 真隊員且有原軍官資格，不必先有官職／service。最終一次提交原 `formal_commander`、首長投影、service/order 及舊職位空缺。

R5 接入後，原 Army 可依已驗證的空缺爭奪紀錄接受 NPC 勝者的同一窄就任交易，授權來自真正空缺及有效結果，不要求空缺隊長先批准。國家代任隊長另需真隸屬、任命職責與目標同意；目前沒有正式入口，首包回 `UNSUPPORTED`，同國籍或國官職不能自行代任。

無合法 requester／候選時維持待令與自衛，不從任何無官職軍官隨機抽隊長。隊伍爭奪接任只有此永久空缺分支准入後才可評估。

### 3.4 募兵與生產

首包募兵候選僅同 Site、同勢力、自由、符合原軍營／兵員資格且無進行中互斥作業的原人物；有正式國家時還須同國。對玩家只提示，不能自動編入。

來源有原隊時須來源 `team.roster` 同意，接收須 `team.recruit` 同意，另有本人同意；首包 NPC 僅同國／同勢力、安全閒置、無未收束承諾者接受，玩家必須明示確認。同國不能替代同勢力、容量、停止、裝備及供養守衛。軍營成軍沿 `SiteGarrison.form`，在任隊員移交沿原 `transfer_members_to`。

原 `join_row` 只支援同容器的受控本人回隊，不是通用 NPC 募兵入口。R1 在原 Army／Garrison／Actor 移交 owner 加窄 recruit adapter，明列原退隊 row、原自由 Actor、原駐營兵員的合法來源與 payload；沒有 Actor 真移交路徑的來源不得先顯示可募。不放寬全體 `join_row`，不 clone Actor 成另一個 row。

沒有可招募真人時回「無合格原人物」。測試 deploy、人口數加一、免費生成軍官、開面板自動建國都不算募兵。

生產文官只安排原閒置人員、既有工作區／工序、真材料與原成果 holder。自衛、已接受作業、原疲勞休息規則優先；科技改良另走科技計畫，不因任官即學會。

### 3.5 人事 配裝與遷移

任免、分類變更、派駐、拆併、駐營、成軍以同一份最終方案預檢官職、兵種、順位、供養、持物容量、必要卸裝及實際圖集准入；通過後才同步提交。名冊搬動沿 `_roster_metadata/_install_roster` 及原 Garrison 交易，保留原人、能力、性格、名稱和物品。

官職屬組織，不隨人複製：來源離員的職位空缺、職責留來源；接收方須另有合法目標官職才能投影為幹部，否則按已明示方案成為普通成員或整份拒絕。不得沿舊 transfer 把來源 service/order 直接合入接收隊。新拆隊在同一名冊候選明選合法原軍官為 formal、建立自己的 head 與預設制度；不能複製來源整份 offices，也不靠 `_select_commander` 隨機兜底。

F07 的提交候選包含兩隊 offices/revision、最終 holder 成員資格、service/order 與 formal 投影，clear 後恢復已驗最終態。提交中不讓 step／通知回呼觀察一隊已改、另一隊未改的半成品；全部完成才發原通知，不新增交易管理器。

原 Army／Garrison 軍職 setter 改為同 owner 的窄 prepare／commit：預檢不得先呼叫會立即改 role、能力、RNG 或 settle 的 setter。`HAS_APPOINTMENT` 只阻擋最終方案仍需 officer 的武官／軍令身份，civil 幹部可合法降為 soldier 且保留文官位。Garrison 不再拿當下受控者 faction 代替 NPC 首長 requester；全部官職、兵種、披風、圖集與能力方案通過才一次改角色。

文官任職不自動給披風。現有原軍官資格、合法武官任職、真正國家配裝職責的披風規則分開驗；不能繼續用「全體 service」替 civil 授權。卸裝失敗整份拒絕，物品不刪、不丟。

`team.equip` 可由文官合法負責：原 `_team_issue_context` 以該職責 resolve 驗下令權，`_team_person_present` 改為各角色所需的原人、成員、清醒、自由與在場判定，不能把下令者、代表或一般兵員一律當軍官。已接受 job 提交只重查各人必要身體／實物條件，不重新要求原 requester 仍持該職責；軍事指揮檢查保持獨立。

舊幹部可能多於現有真職責。遷移先讀舊 service／順位為輸入，給可合法配置的真官職；不足時回 `MIGRATION_REQUIRED`，保留原舊檔與現場，要求一份完整人事及配裝方案。不能造閒職、複製權限，也不能永久保留無官職幹部後宣稱遷移完成。未完成遷移的舊資料不得送入新 AI 或 Crowd；可提供唯讀資料與修復預覽，原文件不覆寫。

修復預覽基於已通過舊 schema 的暫存候選及原正式隊長身份，不要求先 bind 成新場景或先取得新 service。允許明示保留原人／軍官資格、解除超額幹部投影、重配真職責；不能自動刪人或卸裝。最終修復通過新規才替換現場及輸出新版存檔，取消或失敗仍保留原檔與原場景。

## 4. 人物 組織與國庫的資料歸屬

### 4.1 引用與唯一 owner

- 跨 Site 人物引用使用原完整 `PersonRef {site_id, person_id}`；`PLAYER_MEMBER` 不是人物 ID，不能保存為任職者或投票者。
- 同 Site 的舊整數 holder 可留相容解碼，但家族跨 Site holder／候選／同族關係必須保留完整引用。舊家族同 ID 有多個 Site 候選時拒絕猜測，回遷移修復；唯一可證明引用才轉換。
- 地點移交若同一原人更換存放 Site，沿原人物移交交易建立引用對照並更新引用；不得把目的地同號人物當原人。首包新政治交易限同 Site，跨 Site 引用修正與既有家族接續另驗。
- 組織引用用 `{kind, site_id, org_id}`；隊伍沿 team ID、國家沿原 nation ID、聚落沿 settlement ID。家族由原 registry 明示補穩定 family ID，接續只帶同一 registry ID，不另造 FamilyManager。
- 同一原人跨組織兼任時，各命令只使用一份明確組織／職責授權，不能疊加權限。

事件保存發生時的 OrgRef；退隊／改國後仍可結清舊關係，不按結算當刻的新會員身份重掛責任。已失去效力的歷史組織引用只供顯示與去重，不能拿來授權；組織裁撤／重用編號須保留原 lineage 或遷移對照，不能讓舊忠誠套到新組織。

移交只重映射當前可授權引用；已發生事件的去重號、捕獲episode與原始引用保持不可變，另保留原人物對照。不能因location改變重新建立episode、補一份中性忠誠或把兩Site同號人合併。

忠誠、不滿與事件去重資料放原 Army row／Actor 的版本化 `social_state`，轉移沿原人物 payload；不放在畫面、不以暫時 row index 建第二人物表。政治狀態與性格、HP、疲勞、士氣各自驗證。

### 4.2 最小規劃欄位

以下是待施工 schema，不是現有 API：

| owner | 新增內容 | 保存與驗證 |
|---|---|---|
| 原 person row／Actor | `social_state.version`、各原組織的 loyalty、grievance、日事件摘要／最後結算時刻、已證明觀察秒數／最後區間端點、離開意向、捕獲序號 | 忠誠 0–10000、不滿 0–100，真組織引用，日摘要有界；時刻不得在未來，完成量不超過已驗區間；捕獲序號隨原人保存且單調增加 |

分包 schema 不循環：R0 先發布最小 `social_state` v1（原人捕獲序號）及 captivity v3，沒有 G／L 決策；R2 再升 social_state v2 增加組織關係／事件。兩版均由原 Actor／Army／Store 讀寫，R2 不重置既有 episode、時刻或來源標記。R1 offices 分類、R3 admission、R4 treasury/ransom、R5 succession 各包都有自己的版本遷移及舊版唯讀／拒絕界線，不能靠增加未知鍵繞過 validator。

### 4.3 貨幣與國庫

首版新增一種實物資源 `coin`，一單位是一枚遊戲通用幣；無匯率、借貸或抽象財政點。沿 `SiteEnvironment` 的資源名稱／白名單、原 inventory/cargo/stockpile、容量、移轉及 SiteStore 驗證。每枚先沿原資源計一件容量，不能假定個人 20 件載量可搬 100 枚。

貨幣在原 holder 中保存。nation 只引用明示授權、實際屬本國可用的國庫 stockpile／holder；不雙寫 `nation.balance`，不把無主 `site.inventory` 自動當國庫。倉庫的 faction 權限不等於 nation 所有，須由正式建制／管理入口綁國庫，同一來源不得同時綁給兩國，首版各國只綁一個來源。

首包幣從明示情境初始庫存或原合法實物移轉進入。舊檔缺幣為 0，不補錢；沒有國庫就拒絕國家金錢贖回。正式鑄幣、稅收與一般貿易另屬經濟後續，本包不以免費發錢按鈕代替。

## 5. 作業交接與提交契約

### 5.1 三個時點

1. **候選／預覽**：未建正式 job／命令。保存組織、職位、職責與預檢 revision；提交時 revision 不符就重新預檢，不能沿用舊候選扣物。
2. **接受**：原 owner 回成功，建立原 job／訓練令／其他已承諾命令。記錄原下令者、真執行者、所屬組織與職責、接受時 revision；調動職責只交接控制權，不抹除作業。
3. **實物或結果提交**：原 owner 重查原人物、供養時段、版本、材料、容量、空間、目標與受擊／移動等硬限制，仍一次提交。不能因交接就放寬實物守衛。

權限請求先採小 Dictionary：`requester_person_ref, org_ref, position_id, duty_id, expected_revision`。共用原 resolve／refusal；不新增泛用請求框架。立即 resolve 能驗當下合法性，但不等於驗過預檢的 revision，兩件事分別檢查。

### 5.2 交接後的控制權

- A 保留原職務／人物資格，只把職責交 B：原作業繼續，新負責 B 可停止或修改；A 不再能追加新令。
- A 被免職或失去該職責：解除新的下令權，組織已接受作業仍沿其硬條件完成；新負責人可明示取消，不能把免職本身當通用取消原因。
- A 死亡、失能、離隊：只取消原作業確實依賴 A 本人參與／在場／成員資格的部分。若 A 只是原下令者而非必需執行者，原工作人員的已接受作業繼續；訓練若失去必要實體指揮者仍沿原規則停訓。
- 只改名：命令、進度與權限完全不變。
- 代行與恢復：同樣使用此規則，不重啟訓練或五秒換裝。
- 若新負責職位無合法執行者，原已接受工作按原安全條件收束；新的改令／付款／任官暫停。無人不能成為新增命令的授權理由。

整隊修改／取消走 `team.equip` 的 requester-aware 窄入口，重查當前 resolve、revision與真正原job，再呼叫原取消；舊窗口不是授權。job仍由原代表C持有，不為交接把 `_jobs` 搬給B；真正執行者C保留自行中止原動作的權利，原下令者A不再藉取消他人的job發新控制令。

已開始的五秒整隊換裝列為「已接受作業」，保留原交易與單一 job；交接後不再要求原 requester 仍持 `team.equip`，但原 requester 真身仍須符合該 job 原必要身體條件。參與者、庫存或圖集失效仍整批拒絕。

歸降、贖回、接任與叛離在最終交易前仍須最新雙方 consent／引用／revision。人事方案單純交接可以保留已接受的身體步行／計時，但不得保留未執行的新政治選擇或舊價款；最終條件失效不改籍、不扣錢、不釋放。

報價在有效期內固定；只是改名或與此次交易無關的 revision 變動，重新預檢後可保留相同價款，不每次重算性格價格。真正對手／授權／款源／episode 改變則原 offer 失效，新確認完成前不付款。本人由 NPC 轉受控時，先前自動同意、參選或投票不算玩家確認；最後提交重查當下控制權，轉正式選項等待，G／L及觀察進度保留。

## 6. 拘押 忠誠與本人歸降

### 6.1 真入監時間

原 `SitePersonActions.admit_prison` 成功提交時寫 `admitted_at_game_seconds = SiteRuntime.now(data) * 60`；使用原 minute＋phase，不另立時鐘。

原捕獲成功提交時同樣保存 `captured_at_game_seconds`，原人的捕獲序號加一；episode 不使用戰鬥 RNG 或程序全域產號器。忠誠的完整拘押日從捕獲起算，典獄 10／30／50 日主動評估期從入監起算，兩者不可混用。解除後再俘建立新 episode，即使同遊戲秒也不撞舊事件。

同一拘押期移監、換典獄、關閉 AI、存讀檔不改首次入監時刻。結束拘押後再被俘屬新期。讀檔／替換清除暫態評估與候選，持久入監時刻照原紀錄恢復。

舊檔真捕獲／入監時刻不可還原：各自首次遷移用當前已知 Site 時刻、標記 `legacy_observed`，只做一次並保存；未入監者不造入監時刻。UI 說明「舊紀錄從遷移日起計」，不宣稱真歷史、不每次讀檔重新計。

中性／仁厚／嚴酷的 30／10／50 日保留為**典獄主動處置評估期**，不再等同期滿無條件釋放。國家贖回與本人願意歸降可在期滿前提出；期滿仍無可接受去向者保持在監並顯示待辦。

這項處置政策在R3真正受降閉環准入後切換；R0只修入監計時與保存，不提前拿掉第六輪已能執行的釋放流程。後續更新原prison測試須明列「政策改為評估期」，保留舊基準／失敗鏈，並新增不願歸降仍在監及合法人工釋放案例，不能刪掉舊斷言後冒稱同一行為PASS。

### 6.2 忠誠與願歸降門檻

忠誠 `L` 以萬分位整數 0–10000 保存，畫面顯示 0–100；針對原國家，有國家時不把隊伍士氣當國家忠誠。無國家時使用被俘當時可證明的原隊伍關係。被俘時保存此次效忠組織引用，同一拘押期不因搬隊或免職而換對象。

無可證明原組織者顯示「無原效忠組織」，不建立虛構 OrgRef，不套自動忠誠歸降；正式本人明示同意與合法人道釋放仍可用，NPC 首包列人工處置待辦。

首版新關係基準 6000；已明示的情境值優先。舊檔一次遷移為 6000，不按性格抽值，不消耗軍令／戰鬥 RNG。既有關係在換隊、失去官職或存讀時不重置。

本人願接受歸降的門檻：

```text
Δ軸 = 軸值 − 50
T = clamp(3000 + 20·Δ野心 − 20·Δ守法 − 10·Δ勇猛, 1000, 6000)
願意 = L <= T
```

野心較高較願換門庭；守法較高更難背離原組織；勇猛較高更願承受拘押而非改投。忠誠與性格是兩份資料；低忠誠不直接改傷害、士氣或人格。

| 性格，其餘軸 50 | 願歸降門檻 | 固定邊界 |
|---|---|---|
| 全中性 | 30 | L=30 願意，30.01 不願意 |
| 野心 100 | 40 | L=35 時相對中性首個分歧 |
| 守法 100 | 20 | L=25 時中性願意、此人不願 |

忠誠一般日事件在第8節更新；拘押到點及解除前由同一結算候選補齊，不由典獄每輪固定再扣一次。清醒、自由意願、原人在監／拘押、真正 offer 可達與政治交易守衛均為硬限制。玩家俘虜只顯示選擇，永不由 AI 自動改籍。

`surrender_pending` 仍表示原潰退待俘，不改成政治歸降；政治歸降使用獨立已接受 offer 的窄交易資料。

### 6.3 拘押方受降與提交

本人願意不等於拘押方必收。本聚落 `settlement.prison` 典獄決定接受處置；改入新國另需該國 `nation.admission`（預設文官「戶籍官」）同意。目標國無合法職責執行者、無合法出口／原人移交路徑時回等待，不先釋放再補國籍。

首版拘押方 AI 在本人願意、同 Site 可完成交易、目標國明確接收時接受；不引入外交信任、暗殺或強迫效忠判定。沒有目標國則不能把「低忠誠」直接改成某隊士兵。

一次預檢並同步提交：原拘押與 episode → 本人最新 L／T／同意 → 典獄與接收方職責 → 原出口與人物移交 → 舊／新 nation members 唯一性 → 舊官職空缺 → 原供養移轉 → 原 holder 保全。任一步失敗全不提交。

供養以政治交易的**最終歸屬**一次 prepare＋commit：候選包含解除後真 home、原 row／Actor 最終態及本次交易上下文。現有 release 預檢會回原隊、被俘 membership_change 仍留拘押方；不能串接「先release再leave／transfer」後讓舊 prepared 回寫原隊。原 Supply 只識別並允許已驗證的本次 job，不能把自身 BUSY 誤拒，也不能豁免其他互斥 job；本人餐份與移轉歷史只搬一次。

原國籍沿 `equipment_nations.members`，戰鬥歸屬沿原 Army／Actor；兩者分開一致更新。nation_id 不等於 faction_id，目標 offer 必須明示合法目的 owner／faction，不由國名猜勢力。Army rows 沒有有效的逐人 faction；收降一人須搬原 row 到合法目的戰鬥 owner、保持未編入隊的 member=false，或沿真 Actor 移交。不能改原100人整隊 faction，也不能只塞無效的 row.faction。無目的容器／真安裝路徑則等待，不能假稱已受降。一般 `transfer_members_to` 的同勢力規則不放寬。現 Actor 存檔只准原 player／npc，不能為任意 row clone 第三個 Actor 來繞過移交；擴 Actor 容器屬另案。

政治候選一併驗真受影響的 formal/acting/current、service/order/head 及原 corps 引用。faction 變更使舊軍團任命不相容時，沿原 owner 合法交接／空缺；不能把全部 corps 刪掉，亦不能留下下一次 Store 必拒的跨勢力軍權。單純離族／退隊／改國籍而未改戰鬥歸屬，只解除此次退出組織授予或已失格的權力，其他組織獨立合法任職可保留，不能一鍵全清。

歸降後不自動取得官職、披風、配裝、研究知識或軍令；先成為目標國原真人成員，募兵與任官另走正式入口。封存物、被取走裝備不自動還原，沿原物權入口處理。

### 6.4 期滿處置與押送順序

每輪優先完成可合法押送，再處理贖回／歸降／期滿待辦；計時與日社會狀態先更新，不因成功押送提前 return 而漏記已在監者。

嚴酷先押軍官多的組，仁厚先安置 HP 最低的組，中性按完整原看守引用；同分按穩定引用。疲勞、作業互斥、供養與路徑沿原入口。

任意人道釋放保留玩家／合法典獄明示命令，不把「派系仍敵對」或「忠誠低」當作已無敵意的證明。首版 AI 不用模糊「已無敵意」自動放敵人，改用可驗的願歸降＋接收、或完成贖回；後續外交承諾另案。

## 7. 國家金錢贖回

### 7.1 權責與價格

新增國家 `nation.ransom`，預設文官「贖務官」，只決定本國成員的贖金支出；元首代行沿原職位規則。拘押方同意沿 `settlement.prison`。不能假切 `controlled_person_id` 讓 NPC 付款。

首包 coin 贖回限聚落管轄內、已有合法典獄處置入口的戰俘營；野外仍保留原100日份糧模式，未接野外收款／拘押授權前明示金錢模式未支援，不用典獄權跨域處分野外俘虜。

首版單人價格以原人在被俘當時的已保存官職判定，任一真組織首長優先於普通官員，不因跨組織兼任重複加價，免職不改此次身價：

身價快照讀原正式任職持有人及Army formal，不讀當下 duty decider；本人昏迷、代行者正在下令，不代表正式首長變成普通人。捕獲改身體／資格前在同一候選取得快照，成功才寫入episode。

「拘押方性格」只讀此offer真正 `settlement.prison` resolve 的決策者，保存其完整PersonRef與所讀節儉／仁厚值，不能讀最初captor、接觸代表或隨意隊長。人格沒有內容revision時比較所讀值即可，schema版號不是內容revision；決策者或人格前提改變使原offer失效，重新報價／同意後才續提交，合法已接受步行／計時可保留。

```text
基價 = 10 + (被俘時普通在任官員 ? 5 : 0) + (被俘時首長 ? 15 : 0)
首長不重複加普通官員的 5
報價 = clamp(基價 + round_half_away((拘押方節儉−50)/10)
                    − round_half_away((拘押方仁厚−50)/10), 5, 35) coin
```

`round_half_away` 四捨五入，恰半時遠離零：+0.5→+1、−0.5→−1；不得讓 GD／Python／native 使用不同預設。全端點最高報價為 35。

中性普通人 10、官員 15、首長 25；仁厚降低要求，節儉提高要求。捕獲成功時在原 captivity 保存當時官職等級，首長不重複當普通官員。舊檔無法證明被俘時身份者按普通人基價 10、標記 `legacy_unknown`，不讀現任官職回填身價。報價由原 offer 保存雙方、人物、價款、有效期限與 revision，首版有效一遊戲日；本人存活／拘押或相關權責、來源改變即失效，不每分鐘重抽價格。

國家 AI 預設每人上限35、每日總額50、付款後至少留20 coin；政策由合法元首經同一正式設定入口明示授權後才准 AI 支出。玩家元首用國家頁設定；新建NPC國家可由合法NPC元首經真requester入口初始化上述政策，行為在國家頁可見，不能假切控制人物。舊檔維持未授權，沒有真國庫亦不初始化。贖務官可在授權內接受報價，不可超額。首長／官員／重傷／其他國民按此序，同序原引用較小者先；玩家可查看、取消或手動改合法政策。

當日支出必存對應的原遊戲日期，跨日才清零；政策、國庫改綁、換元首、存讀檔不清零。到期offer不付款，最後跨日仍按提交當日預算重驗。

幣不足、收方容量不足、來源非本國授權、需要搬運而未到位皆等待／拒絕，不用糧食或虛擬餘額頂替。國家沒有明示國庫及政策時 AI 不花錢。

### 7.2 沿原贖回與出監 owner 擴充

保留舊 100 日份糧食贖回模式及其原驗收。原 `SitePersonActions` 的 ransom／prison_release 作業增加明確 `payment_mode=coin` 與國家 requester 上下文，原 `SiteCaptivitySupply` 擴充付款來源查詢，實物扣入仍由 Runtime／原 holder 交易處理。

真付款代表與拘押方代表須在原合法接觸位置；幣源與收款 holder 須可達、容量足夠。超出個人載量時使用既有合法車具／庫房交易端點或先完成原運輸，不能讓代表攜帶無限貨物。

coin 模式分別驗：`nation.ransom` 的真支出授權、代表本人的身體／指揮同意、當前 `settlement.prison` 拘押處置權，以及收款 holder 的真歸屬。不能套舊食糧模式「付款方等於俘虜faction、兩方均軍隊指揮者、收款代表屬最初captor原隊」的假設。原 captor 已死而合法典獄接任、同國國民處於另一faction隊伍，仍能以當前真權責預檢；舊100糧 guard 保留。

首包只從當下唯一已綁的公用國庫 holder 直接付款。若先搬幣，沿原實物移轉完成，再由合法國家管理入口改綁到目的公用holder、作廢舊offer並重新預檢；每日已支付額不因改綁重置。不從原庫重扣、不把混合私人cargo當國庫，也不建運錢影子帳本。付款與收款 holder 必須不是同一原實物字典／同一引用，保持幣總量守恆，拒絕自付自收免費解俘。

在監金錢贖回須把原出口預約與解綁結果放進同一最終交易。**不可先免費出監再扣錢。** 沿原步行／接觸與供養收束進入原作業，最後重新驗：offer、雙方權責、當日預算、來源／目的版本、真數量、出口、人物、拘押與供養；無 yield 同步扣幣、入收款 holder、解俘與移轉原供養，再記當日支出。

失敗不扣款、不入收方、不解俘；成功不改被贖者國籍／家族，也不重發封存裝備。拘押方所得只存真收款 holder，財政累計不能再當可花餘額。

任職交接保留已接受的身體步行／計時，但新政治確認或價款失效須重新取得雙方同意。移動、受擊、死亡、撤銷、讀檔中斷沿原作業守衛；未完成金錢作業維持原 BUSY 存檔邊界，已完成不重扣。

## 8. 不滿 忠誠更新與可見預兆

### 8.1 更新節拍與事件來源

每原遊戲日結算一次，從共同 Site 時間跨日處理，暫停不動；慢幀補足到已完成原時間，不按畫面幀數或開面板次數更新。事件在原 owner 提交成功後記摘要，日結算消耗一次。無可靠來源者不憑空扣分。

當日供養 coverage 是原 Sustain 已完成供養區間的日內加權值：原每餐6小時、換段會重置coverage，不能取午夜最新餐份或新隊快照。由原 `advance_to` 已完成區間按應供量累積真coverage並記當時責任OrgRef；原 `transfer_ids` 已吃餐份隨本人搬，不能重新發糧或重算。前18小時滿供、後6小時無供，日coverage=75%，只觸發+4。

同一人一天只有一件挨餓政治事件：先算整日coverage及+8／+4，再歸給當日應供而缺供量最多的真責任組織，同量按完整OrgRef穩定順序。不因換了兩隊各加一次；無合法責任組織或敵方囚糧不歸原國的區間，只保留原供養／健康後果，不造國家不滿事件。未滿日、離線未知區間不得當成全天零供。

原 Army 保存當日基準cohort及已去重戰死數：正常以日初正式存活真人，當日新建隊以正式成立瞬間為基準；車輛不算真人。首版新入隊者次日才加入cohort，戰死只有本人屬該cohort且發生時仍屬本隊才計本隊比例，調走後不再算來源。基數0不除、不產生比例事件；首版此限制必須在戰況明細說明，真死亡仍保留，不捏造前一日隊伍。cohort沿原隊快照保存，不建第二人物名冊。

每人對每個真所屬組織有 `G∈[0,100]`。團體事件按責任歸屬只記一次：軍糧／傷亡算隊伍，國家贖回政策與國庫算國家，離族／家族人事算家族。不得同一挨餓事件同時懲罰隊、族、國三次。

|---|---|---|

N = 當日已去重的負向事件總量

### 8.2 完整拘押日與關係收束

日事件在原跨日完成區間結算；拘押滿24小時是獨立到點事件，不等午夜。原60遊戲秒review可發現到點，任何解除／改籍／政治提交前仍純預算到提交時刻的完整日差，先拿候選L判門檻，再把候選社會狀態與政治結果同步提交。

例如 D0 06:00被俘、D1 00:00只過18小時不扣、D1 08:00釋放時已過26小時：解除前必補扣1完整拘押日，不能 erase captivity後漏掉。恰到24小時時可在該次合法review／提交取得新L；失敗不得提前消耗日計數、事件或去重記號。

解除／退隊／改國的最終候選同時收束舊OrgRef截至當步供養結算完成的區間，再切新歸屬；未滿整日部分記已完成摘要、不冒充一整日。日末仍按各責任組織的實際區間合併一次，禁止按午夜新隊重掛舊挨餓、傷亡或免職事件。成功贖回的G−20／L+1000同一次提交記為待日結事件及去重號，不提前再套一次；日結後只保留已處理記號，讀檔不重發。

### 8.3 忠誠連動

忠誠 L 的一般事件在同一次日結算更新；完整拘押日沿第8.2到點／收束候選計一次：

- 對該組織的 L 減 `50*P` 萬分位（每計入 1 點正向事件量減 0.5 點），不按 G 夾值後的差額扣；G 已滿 100 或同日有贖回負向事件仍只扣這一次。
- 在敵方拘押且有原組織關係，L 每完整拘押日減 100（1 點），只更新捕獲時保存的效忠組織。按本拘押期已完成的 24 小時數與保存的已結算日數之差結算，跨午夜不等於滿一日；同一期移監或讀檔不重扣。當日囚糧不足不再對原國家追加一次挨餓懲罰，囚糧責任不能錯算原國家。
- 自由、滿供養、無正向不滿事件且履行本組織正常職務者，L 加 50（0.5 點）；G 自然下降不再額外加一次。
- 本組織成功贖回本人，L 加 1000（10 點），與 G−20 同事件但各欄僅一次。
- 最後將 L 夾到 0–10000。性格本身不每日抽值。

例：中性囚犯 L=60、無其他事件，完整拘押30日後 L=30，達中性願歸降門檻；守法100需降到20，即40日；野心100降到40，即20日。典獄不願或目標國未接收時仍不改籍。

### 8.4 叛離門檻與預兆

```text
H = clamp(70 − floor(2·(野心−50)/5) + floor(2·(守法−50)/5), 30,95)
```

非受控者對該組織 `G>=H` 持續滿三遊戲日後才成立離開意向；未成立前 G 低於 H 即清除觀察進度，成立後降到 `H−10` 以下才清除意向，形成遲滯。持續觀察的已證明遊戲秒數、最後區間端點與意向狀態保存，直接日事件跳過門檻不跳過三日觀察。正常連續Site區間等同三日；缺失的離線區間依第11節不冒充已證明觀察。

戰鬥、受俘、失能或未收束作業只阻擋最終執行，不因每天生產／訓練而重置不滿觀察；本人回到原安全邊界才評估是否實際退出。若本人仍受俘，退出不能取代第6節拘押／受降交易。

人物狀態與組織頁顯示本人 G、門檻、當日主要原因、最後結算日期，並顯示「不滿」「可能離開」「已提出離開意向」：G≥30 顯不滿；G≥max(30,H−10) 顯可能離開；到H開始顯剩餘觀察日。若門檻30，首個到門檻日仍有三日可見觀察，不當天消失。

玩家所屬組織首次跨警戒、意向成立、取消、實際離開各提示一次；面板不暴露不存在的心靈閱讀系統，而是本版明示的遊戲可見狀態。受控者從不自動叛離或投票。

## 9. 指定繼承與爭奪接任

### 9.1 觸發與範圍

在任首長不因本系統被逼宮。暫時失格仍按代行；只有永久空缺且現場穩定、原繼承不能完成時處理接任。

優先序：正式已指定且當時合法的繼承人 → 隊伍合法武官順位／家族在場受控族人指定 → 無指定可用者的爭奪。國家無指定繼承人預設爭奪，聚落亦同；家族受控族人在場仍由玩家指定。隊伍無幹部分支須先完成第3.3入口，不先改其原順位。

**勢力首長（勢力規劃 §3.3）：** 國家元首就是其所屬勢力的首長，本節產生的新元首同次成為勢力首長，名冊不另存。沒有國家的勢力，首長由首長所屬家族接任（勢力規劃 FQ3）：首長本人是家主時，依本節家族優先序產生的新家主同時成為勢力首長；不是家主時由現任家主接任；接任者須清醒、自由、在世且屬本勢力，無合格族人則勢力首長空缺、外交關係凍結。首版只在首長所在 Site 的族人中找。

空缺累積一遊戲日已證明政務區間才開爭奪，爭奪期再兩遊戲日；連續active時等同空缺第三日到期，缺失離線區間依第11節保留原進度。到期有合法候選及有效方案才結算；沒有候選或條件失效則顯示空缺待辦，保留同一 episode 重新預檢，不每輪重開時限或重加落敗不滿。暫停凍結；指定繼承人回歸／玩家合法補任先提交則取消爭奪，不覆寫已就任首長。

### 9.2 候選 支持與結果

候選是組織原成員、符合該首長基礎資格、清醒自由且在原要求範圍；在任官員或野心≥60者可參選。軍事首長仍要原軍官資格，政治官職不自動授予軍權。沒有候選維持空缺。

首包有效支持者限同 Site 已載入、清醒自由、有組織投票資格的真成員；未載入遠地人物不造票。受控人物必須明示「參選並接受合法就任」才入候選池，未回應不參選；支持選項未回應才視為棄權。NPC候選按原資格評估，其他NPC有合法候選即支持最高分者。允許候選自投但仍每人一票；玩家自投也需明示，不因參選自動造一票。

20%分母為該次有效成員集合，含受控棄權者，排除遠地／死亡／失格者；分母0不作比例。支持度在有效結算時用同一輪原狀態重算，玩家已明示的合法票保留。最終再驗控制權：原NPC參選／自動票轉為受控後即等待玩家確認，不能替玩家卸任或得位。

首版每位 NPC 對候選的整數分數：

```text
score = 2·leadership + floor(tactics/2) + (已在任官職 ? 10 : 0)
        + (為已登錄同族 ? floor((支持者重家族−50)/2) : 0)
        − floor(abs(支持者G−候選G)/2) − floor(候選G/5)
```

缺能力沿原中性基準，不亂抽新值；同分按完整 PersonRef 穩定順序。最高支持人數勝出；支持同票再比同一份 leadership，再比原引用。所有數字與支持結果可在組織頁查看。

全零票或無合法候選不依能力／引用硬選首長，維持空缺待辦。已有有效非零票但同票時才使用上述同票規則；後續候選／投票變動仍沿同一空缺episode重驗，不重開倒數或重加落敗G。

得位者若已有該組織其他官職，在同份方案把舊職位變空缺、保留其職責，再就任首長；不可要求「空缺首長先幫他卸任」。原 `appoint_nation_head` 的情境入口須加窄正式空缺就任交易；聚落 `claim_head` 的 controlled 限制改為真 requester／空缺授權；家族／隊伍同樣沿各原 owner，不造 ElectionManager。

結果提交前再驗組織 revision、真正空缺、候選資格與支持者唯一性；任一步失效重新評估或取消，不部分卸任。因有效結果落敗者G+10；支持者不自動改勢力。

## 10. 個人叛離 家族離族與投奔

### 10.1 各組織分開處理

- **離族**：允許 NPC 退出原家族組織。移除 active members 與該族官職，記原 registry 的離族歷史；既有血緣引用若有、原人物技藝、個人資產保留。家族組織成員不等於生物血緣，缺真血緣資料時不宣稱有。
- **退隊**：解除該隊名冊、官職與供養歸屬，原人轉為同 Site 的自由原人物；不因此改國籍。
- **叛國**：解除原國 members 與官職，未投奔前為無國籍原人物；不因離族自動叛國，不因叛國自動離族。
- **離開聚落治理**：只解除該聚落官職／正式所屬關係；房屋、土地與公庫歸屬沿原法律／建物 owner，不能清空他人房屋記錄冒作遷徙。

離族可由受控本人明示操作；NPC 自主離族是本輪批准的新自動事件，取代舊「所有家族名冊變動只能人工」的例外，但家主 AI 仍不能任意踢人。首長自己退出時同一交易產生真正空缺，再按第9節接任。

### 10.2 個人叛離條件

套第8.4門檻與三日預兆。失能、被俘、戰鬥、在途承諾／未完成物資作業均等待原安全邊界，不強制消失或穿越預約。依原人當前組織責任決定退出哪一組織；跨組織另各自判定，不一鍵全清。

首包先完成成為同 Site 無所屬原人物；其後才加入投奔同 Site 敵對國家。整隊或整座聚落叛離時，目的地可以是新建的 `rebel` 勢力（勢力規劃 §4.4，F5）：正式隊長叛離則整隊改屬新勢力、隊長為首長，聚落首長叛離則中心與管轄內本勢力建物改屬新勢力；不跟隨者依 §10.1 退隊。個人叛離仍照本節，不能藉新勢力繞過原人移交。沒有正式敵國接收入口、不在可達範圍或原人／供養移交前置不足時，不能直接改 `faction_id`。國庫只屬金錢贖回前置，不是免費歸降或投奔的條件。

正式政治退出／採納在原 Army、nation、family、settlement owner 加窄交易：搬原 row 或 Actor，不複製人物；原 ID／PersonRef、HP／KO／疲勞、能力、性格、個人技藝與 holder 保留。原隊共享糧、國庫、車輛、建物與組織物資不隨身帶走；原被封存物及公物沿現有物權判斷。

本人若還是其他囚犯的看守／captor，這些非參與囚犯不能被原 Supply followers 搬成同行者。原 Captivity／Prison／Supply 候選須合法交接看守及原餵養，保留其episode、效忠與已結算拘押日數；歷史captor只作歷史，不冒充當前看管權。沒有合法接手入口就等候，不能清captivity、免費釋放或挾帶不在政治名單的原人。

### 10.3 落敗者與支持者

候選落敗，野心>70、守法<40、支持者占有效組織人數至少20%時，可提出同行邀請、形成候選名單；這是同行准入，不縮短本人G門檻或三日預兆。落敗G+10仍只計原結果一次，不另加隱藏加速值。

支持者每人獨立符合叛離條件、願意同行且不是受控者才加入。當本批任何一人的原引用、物權、供養、出口或目標接收失效，先重新形成可完整提交的名單，禁止提交一半又回頭補另一半。

多人的原子政治交易第一版上限10真人／批；更大支持群按穩定引用分批，每批重新預檢，不宣稱全組織集體改陣營。玩家可看到每批離開名單；此上限是首版處理額度，不改組織名額。

def clamp(x, low, high):
    return max(low, min(high, x))

def surrender_threshold(ambition=50, lawful=50, risk=50):
    return clamp(3000 + 20*(ambition-50) - 20*(lawful-50)
                 - 10*(risk-50), 1000, 6000)

def departure_threshold(ambition=50, lawful=50):
    return clamp(70 - floor(2*(ambition-50)/5)
                 + floor(2*(lawful-50)/5), 30, 95)

def decay(ambition=50, lawful=50):
    return 1 + max(0, 50-ambition)//25 + max(0, lawful-50)//25

def round_tenths(value):
    return (value+5)//10 if value >= 0 else -((-value+5)//10)

def ransom_price(tier=0, thrift=50, mercy=50):
    return clamp((10, 15, 25)[tier] + round_tenths(thrift-50)
                 - round_tenths(mercy-50), 5, 35)

def social_day(g, loyalty, positive, negative=0, rescued=False):
    p = min(20, positive)
    return (clamp(g+p+negative-decay(), 0, 100),
            clamp(loyalty-50*p+(1000 if rescued else 0), 0, 10000))

def custody_candidate(loyalty, captured_at, now, settled_days):
    full_days = floor((now-captured_at)/86400)
    assert 0 <= captured_at <= now and 0 <= settled_days <= full_days
    return clamp(loyalty-100*(full_days-settled_days), 0, 10000), full_days
