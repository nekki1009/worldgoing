# 土匪勢力規格補充 V0.1（bandit kind）

日期：2026-11-09。來源：Nekki 於「查勢力劃分中是否有土匪」討論串的決定（BQ1 = A，新增 `bandit` 類型）。本文是 [勢力與外交規格 V0.7](../FACTION_DIPLOMACY_SPECIFICATION.md) 的補充，不改寫原文；原文沒寫到的地方以本文為準，兩者衝突時以本文明示契約為準並在 §13 列出要回頭改原文的地方。只做規劃，不改程式。

這是遊戲底層邏輯，不綁定台灣地圖；台灣情境要不要放土匪、放幾伙，另案。

編號慣例沿原規格：決定 **BQ-n**、驗收 **BA-nn**、階段 **B1–B5**。修改時保留既有編號，新增接在後面。

## 0. 一句話設計

**土匪是法外的武裝團夥：沒有國家、不治理聚落、對所有人敵對，靠劫掠過活，只能被剿滅或招安；坐大了可以起義變成叛軍，叛軍敗了也可能落草變成土匪。**

## 1. 現況與叛軍的差別

### 1.1 現況

- `FACTION_DIPLOMACY_SPECIFICATION.md` §3.1：`kind` 只有 `player / npc / rebel`，且明訂「是建立來源標籤，不授予權限」。
- `scripts/region_lab/region_faction_query.gd` 第 51 行驗證器只接受這三種；其他值回 `CORRUPT_SAVE`。中立勢力 `NEUTRAL_FACTION_ID = 255`。
- `scripts/region_lab/region_peerage.gd` `rebel()`：只有 `independent`（自立為王）與 `defect`（帶封地改投）兩種結果。
- 規劃稿 `reports/faction-plan.md` §3.2 只有一句「沒有國家的勢力可以存在（土匪、剛分裂的叛軍、遊戲初期的玩家）」，沒有規則。
- 貿易計畫 V0.5 已有商隊「風險折價（依路線上已知敵情）」與 **TR-55 劫掠**（商隊被打敗，貨留現場遺物容器），但沒有會主動劫商隊的勢力。

### 1.2 土匪與叛軍的差別

| 項目 | 叛軍 `rebel`（現有） | 土匪 `bandit`（本文） |
| --- | --- | --- |
| 來源 | 從既有勢力分裂：正式隊長或聚落首長跨過叛離門檻，經預兆、觀察期、支持名單 | 不必從勢力分出：潰兵、逃兵、逃出的俘虜、流民、情境配置，或叛軍潰敗落草 |
| 帶走什麼 | 整隊或整座聚落含建物與職位 | 只有人、隨身物品與車輛；沒有聚落 |
| 目標 | 獨立或改投，之後建國、治理 | 劫掠、勒索、收買路錢；不治理 |
| 據點 | 聚落（可建國、等級、職位） | 山寨：非正式據點，不是聚落，不能建中心 |
| 佔領聚落 | 可以 | **不可以**；`settlement.owner_faction` 永遠不會是 bandit |
| 外交 | 宣戰、講和、停戰、歸附全套 | **沒有**；對所有勢力（含中立）恆敵對，唯一出口是招安 |
| 首長 | 隊長／聚落首長；家族接任 | 頭目；由在場威望最高者接任（不走家族） |
| 爵位 | 可為王、可帶封地 | 無爵位；招安後才可能受爵 |
| 聲望 | 自立 −30 / 改投 −40 信譽 | 落草 −20 信譽；劫掠不再扣；招安後信譽照原規則回升 |
| 滅亡 | 完整 coverage 無活人無建物無聚落 | 同一規則，但多半先「潰散」成無所屬個人 |
| 轉換 | 建國→正式勢力 | 起義→`rebel`；叛軍落草→`bandit` |

**結論：差別是整套權限，不只是標籤。** 所以 `kind=bandit` 帶自己的規則組，是原規格「kind 不授權」原則的明示例外（BQ1）。

## 2. 設計原則

1. **一個欄位決定一組規則。** `kind=bandit` 由同一個 `RegionFactionQuery.is_bandit(registry, id)` 入口判定；外交、佔領、市集、招安、滅亡各處都呼叫它，不各自比對字串。
2. **沿用現有容器，不造第二套人。** 土匪仍是一般 faction entry、一般 party、一般 crowd 陣營；Site 本地 0–254 映射、crowd 存檔、名冊移交全部照原規則。沒有「隱藏逐兵 faction」。
3. **只收窄，不新增權力。** 土匪拿掉的是宣戰、簽約、歸附、佔領、建國、爵位；其餘（移動、戰鬥、俘虜、物資、疲勞、俘虜逃脫）全照原規則。
4. **數值用建議值先做，有問題再調。**（沿 11/06 科技數值規則）本文所有門檻與係數都是建議值，標在 §12，不逐項請示。
5. **不補造離線政治。** 畫面外土匪只做 10A 允許的公式戰鬥與每日一次簡化決策；不補算觀察期、投票、繼承。

## 3. 名冊與資料

### 3.1 entry 擴充

| 欄位 | 契約 |
| --- | --- |
| `kind` | 新增合法值 `bandit`；驗證器白名單改為 `player / npc / rebel / bandit` |
| `leader_ref` | bandit 必填（頭目）；可為空的時間只在接任交易內 |
| `nation_ref` | bandit 恆空；驗證器拒絕有值 |
| `duty_ai` | bandit 固定 `false`（沒有正式外交可主動）；劫掠 AI 另有開關見 §3.2 |
| `bandit` | 僅 bandit 有，其他 kind 必須沒有此鍵。子欄位見下 |

`bandit` 子表：

| 子欄位 | 契約 |
| --- | --- |
| `origin` | `scenario / rout / desertion / escaped_captive / refugee / fallen_rebel` 建立來源，只做顯示與統計 |
| `lair` | `null` 或 `{site_id, cell}`；山寨位置，§5.2 |
| `raid_ai` | bool；NPC 頭目是否主動選劫掠目標；玩家頭目固定 false |
| `heat` | 0–100 整數；最近被官府追剿的程度，影響換寨與目標選擇，§8 |
| `attacked_day` | 選填整數；最近一次被官方勢力攻打的遊戲日（BQ7）。 |
| `pursued` | 選填 {勢力 id: {day, home}}；各正式勢力最近一次出兵剿這伙的遊戲日與出發 Site（BQ8）。 |
| `converted_from` | `null` 或 `{kind, at}`；由 rebel 落草時記原 kind 與時刻，§9 |

`heat`、`lair` 存在 Slot 名冊，不在 Site 複製。

### 3.2 關係表

- `faction_relations` 中 bandit 與任何其他 faction 的 pair 恆為 `hostile`；`RegionDiplomacy.hostile()` 對含 bandit 的 pair 直接回 true，不查表、不查停戰。
- bandit 與 `NEUTRAL_FACTION_ID` 也敵對（中立玩家會被劫）。
- bandit 與 bandit：**不是盟友**（沿「中立 vs 中立不是盟友」同一原則），各伙獨立；是否互相攻擊由現場原敵對判定（不同 faction → 敵對）。
- `treaty_between / at_peace / in_breach_window` 對 bandit 回空、false、false。

### 3.3 保存與遷移

- Slot schema 版本 +1；舊檔沒有 bandit，遷移不造資料，只有白名單放寬。
- `bandit` 子表缺鍵時用預設 `{origin:"scenario", lair:null, raid_ai:true, heat:0, converted_from:null}` 補齊，但只對 `kind=bandit` 補。
- crowd 存檔：土匪陣營走原「全域 id + 本地映射」規則，不另加欄位。

## 4. 土匪怎麼產生

首包只做 **A 情境配置** 與 **B 潰兵成伙**，其餘列為後續（B4）。

| 來源 | 條件 | 說明 |
| --- | --- | --- |
| A 情境配置 | 情境檔列出 bandit entry、頭目、人數、山寨 | 和情境勢力同一入口；可從 0 編號 |
| B 潰兵成伙 | 一場戰鬥結束後，同一方潰逃且未被俘、未歸隊的人 ≥ 3，且 7 遊戲日內沒回到本勢力任何聚落或隊伍 | 原勢力已滅亡或潰逃者所屬隊伍已不存在時才成伙；有家可歸的不自動變土匪。頭目＝其中威望最高者 |
| C 逃兵 | 在途旅隊斷糧 ≥ 3 日或士氣跨門檻，個人叛離條件成立（職位計畫 §10.2） | 離隊後 7 日無所屬，與其他無所屬者在同 Site 聚成 ≥ 3 人即成伙 |
| D 逃出的俘虜 | 俘虜逃脫成功（原「無守衛即逃脫」規則）後 7 日無所屬 | 同 C 的聚集規則 |
| E 流民 | 冷 Site 民生摘要（10A D5）供養覆蓋連續 ≤ 50% 達 10 日 | 每 10 日按缺口人數的 10% 生成無所屬流民，再按 C 聚集。只在 10A 公式真正算出供養時觸發，不補造 |
| F 叛軍落草 | §9.2 | kind 轉換，不是新建 |

成伙＝呼叫 `RegionFactionQuery.allocate(..., {kind:"bandit", leader_ref, bandit:{origin}})`；一次交易內同時完成人員改 faction、頭目設定與山寨選址（§5.2），失敗整筆拒絕。受控人物**從不**被自動成伙；玩家只能在主選單選「落草」開局（§10）或在遊戲中明示選擇。

## 5. 土匪做什麼

### 5.1 三種營生

| 營生 | 對象 | 規則 |
| --- | --- | --- |
| 劫商隊 | NPC 商隊、玩家旅隊、任何在途隊伍 | 在途遇敵走原 R1-U 截停；打贏沿 **TR-55**，貨留現場，土匪再撿走（原遺物撿取入口）。不新增「自動搬貨」 |
| 收買路錢 | 在途隊伍 | 相遇時土匪方戰力 ≥ 對方 1.5 倍可提出：付「人數 × 2 日盤纏等值」放行。NPC 隊伍依頭目貪婪／對方膽量決定付或打；玩家出選項：付、打、逃。付了就是一次有效放行，同一伙 3 日內不再截同一隊 |
| 勒索聚落 | 山寨 2 個 Site 距離內的聚落 | 每 30 日向聚落首長提「保護費」：聚落人口 × 1 日糧等值。付了 30 日內不劫該聚落周邊；不付則該聚落周邊路線風險提高（§7） |

土匪**不能**：圍城、攻中心、改 `settlement.owner_faction`、建國、受封、派信差、簽任何協定。打進聚落只能劫掠倉庫（走原劫掠／合法換手入口），劫完離開，聚落擁有者不變，不走 `fall_to`。

### 5.2 山寨

- 山寨是一個 `{site_id, cell}`，不是聚落；沒有中心、等級、職位、國籍。
- 選址：成伙時在成伙 Site 內選離所有聚落中心 ≥ 一個 Site 寬度 1/4、可通行、非水域的格；沒有合格格就選鄰接 Site。情境可直接指定。
- 山寨可被「攻破」：土匪方在山寨所在 Site 的戰鬥中潰散即攻破；山寨清除，存貨留現場遺物。沒有「佔領山寨」。
- `heat ≥ 70` 且最近 10 日內被官方勢力攻打過，頭目每日決策才換寨：移到鄰接 Site 重選址，heat 歸 30（BQ7）。
- `heat ≥ 70` 但沒有被攻打：蟄伏，當天不勒索、不劫掠、不銷贓，等熱度降下來；有招安提議仍可接受（BQ7）。

### 5.3 內部

- 頭目有隊長權限（原 captain）；分隊沿 PARTY SPLIT 規則（需幹部），土匪的幹部＝頭目指定。
- 沒有職位系統、沒有家族接任。頭目死亡／永久失格：在場威望最高者接任，同一次提交；全員被俘或無人則 §8。
- 招募：只能收無所屬者與自願落草者（§10 玩家、§4 C/D/E NPC），不能從有勢力的隊伍「招降」；要收編對方整隊只能等對方潰散。

## 6. 招安

招安是土匪的唯一外交出口，也是正式勢力處置土匪的唯二方式之一（另一是剿滅）。

1. **當面。** 沿 11/04「投靠必須當面見官」規則：招安方的首長或持有「受降／歸附」職責的官員，與土匪頭目同 Site、同時清醒自由且不在戰鬥中；不能派信差遠端招安。任一方可提。
2. **接受分數。** 招安方沿既有「首長接受」公式：`(100 − 人格差)×0.5 + 野心×0.3 + min(1, 土匪戰力/當地戰力)×20 ≥ 50`，加聲望計畫的有界項（頭目信譽 ×0.15，min(10, 威望/5)）。土匪信譽通常是負的，所以剛落草的伙難被招安，是設計意圖。
3. **頭目的意願。** 頭目用「跟隨」公式對招安方首長：`(100 − 與對方首長人格差)×0.6 + (100 − 與自己人格差… 略)` 沿原 officer follow 公式，門檻 55；另加 `heat/5`（追得越緊越想投）。玩家頭目自行決定。
4. **成員逐人決定。** 每名成員對頭目用原 follow 公式；跟的改 faction 入招安方，成為士兵；不跟的留在原 bandit entry，由在場威望最高者接任頭目；若不跟者 < 3 人則潰散為無所屬（§8）。
5. **結果。** 頭目成為招安方的一名軍官（原 officer），**不自動受爵**；招安方首長之後可依爵位規劃另行授爵，男爵起。原 bandit entry 若無人剩下標 `merged`，`merged_into` 指向招安方。
6. **聲望。** 招安成功：招安方首長 威望 +3；頭目信譽不加不減，照聲望計畫從現值回升。剿滅一伙（攻破山寨或全員死亡／被俘）：指揮者 威望 +3，上限每伙一次。
7. **不是歸附。** 招安不走 FQ5 的雙首長歸附合併、不需要 F4 准入、不留協定；它是一次性的人員改 faction 交易，重用「當面投靠」的移交入口。

## 7. 和貿易的接點

- 貿易 §6.2「風險折價（依路線上已知敵情）」的來源之一＝路線經過山寨 2 Site 距離內。折價建議：每個已知山寨 +15%；該聚落 30 日內有繳保護費則該段 0%。
- 「已知」沿情報規則：出發方組織的任何人曾在該 Site 看到土匪或山寨，或被劫過；不是全知。
- TR-55 不改。被劫商隊的出發組織收據標「未完成」並記 `raided_by` faction id，供聲望與 AI 判斷。
- 市集拒絕與 bandit faction 的人交易（市集是聚落建物，聚落對土匪敵對）；土匪銷贓留後續（B5），首包土匪只吃用與囤在山寨。

### 7.1 銷贓（B5b：A 市集暗盤，Nekki 2026-11-22 選 A）

聚落的官方（倉庫、市集掛單、首長）照 §7 拒絕土匪。銷贓是土匪和聚落**平民**之間私下的當面交易，不是官方交易。

1. **誰能賣。** bandit faction 的人（玩家落草或 NPC 土匪），清醒、自由、不在戰鬥中。
2. **跟誰賣。** 同一 Site、聚落勢力的平民：沒有職位、不是士兵或軍官、沒有站崗／工作隊／運送／駕車等職務、不代表倉庫或車輛。走原當面交易（兩格內、雙方空閒），平民用自己身上的東西付。
3. **只賣不買。** 土匪方只能付物品（錢以外）；平民方只能付糧或錢。
4. **半價。** 平民要收到的價值 ≥ 付出價值 × 2 ×（1 + 原議價利潤）。原議價、讓步次數、每日上限照舊。
5. **被看見就不收。** 聚落勢力的職位持有者或帶兵器的人清醒、在視線內（12 格、視線不被擋），平民拒絕（`WATCHED`）。提議、接受和交割的每一幀都判；交割中被看見，交易取消，不移動任何東西。
6. **熱度。** 每成交一筆，該伙 heat +5（`heat_after` 事件 `fence`）。Region 點進行中不能存名冊，所以先記在控制器上，下一個兩步之間（和每日掛鉤同一處）存檔。
7. **NPC 銷贓隊。** 頭目在場、當天沒有其他動作時：
   - 條件：山寨存貨中非糧物品折糧值 ≥ 60，存貨糧 < 全伙人數 × 7；這伙沒有銷贓隊在外；頭目知道 2 個 Site 內有別勢力的聚落（據點強度收據）。
   - 派一支多人隊伍（不含頭目、不含玩家）從山寨出發，每人最多帶 20 件存貨（先帶值錢的）。存貨的減少和任務先存檔，再照商隊規則出發；出發被拒就全部放回。
   - 這趟是一筆商隊任務（`fence: true`，倉庫欄寫 `hoard`），在路上、到達、回頭都照商隊。到了聚落，帶最多貨的人照 2–5 找一位平民賣一次；見面的過程照商隊抽象（平民來找他）。有人看見就不賣，照樣回頭。
   - 回到山寨後，在頭目當天的回合裡，把身上這趟的貨和換到的糧放回存貨；有賣出就 heat +5；任務結束。同一次存檔。
8. **不做。** 銷贓商人身分、贓物標記與失主追回、聚落治安值、黑市價格表（貿易計畫 §1 照舊排除）。
9. **在 Site 裡要注意。** 敵對雙方站在近身範圍內（1.15 格）即使都是「守住」也會互打，交割遇到受擊就取消。所以玩家去暗盤要隔 1.2–2 格，旁邊不能有其他敵對的人。

分兩步：B5b-1 規則 + 玩家銷贓（交易面板顯示「暗盤」）；B5b-2 NPC 銷贓隊。

## 8. 潰散與消滅

- **潰散**（新狀態，只有 bandit 有）：頭目接任失敗（無在場合格者）或成員 < 3 人時，剩餘者全部改為無所屬個人（faction = 中立 255、各自單人隊，沿「中立玩家＝1 人隊」同一容器），entry 標 `extinct`，山寨清除。一次交易完成。
- **消滅**：沿原 §4.3 完整 coverage 規則。「只剩俘虜仍有活人不得消滅」照舊：被俘的頭目仍可被招安（在俘虜狀態下由俘獲方首長當面提，接受後釋放並改 faction）。
- 永久保留 faction id、終止時刻與必要收據，不重用。

## 9. 互轉

### 9.1 起義：bandit → rebel

- 條件：頭目威望 ≥ 30、伙 ≥ 30 人、heat < 50、頭目清醒自由且不在戰鬥中。玩家頭目明示選擇；NPC 頭目每日決策，野心 ≥ 60 才考慮。
- 效果：同一 faction id，`kind` 改 `rebel`，刪除 `bandit` 子表（`converted_from` 的反向紀錄寫入歷史事件）；山寨變成一般營地；之後全部走 rebel 規則：可宣戰、講和、佔聚落、建國、授爵。頭目成為該勢力首長並由 `RegionPeerage.crown_founder` 封王。
- 關係：維持對所有人敵對，但從此可以講和。信譽不變。

### 9.2 落草：rebel → bandit

- 條件：`rebel` 勢力失去所有聚落與封地、首長在世清醒自由、無正式國家（有國家先走國家解散）。
- NPC：達到條件後 30 日內未達成任何講和／歸附則自動落草；玩家：出選項「落草／繼續流亡」，不自動。
- 效果：同一 faction id，`kind` 改 `bandit`，建 `bandit` 子表 `{origin:"fallen_rebel", converted_from:{kind:"rebel", at}}`；所有在途提案作廢、協定終止；首長信譽 −20（落草）；爵位紀錄：首長保留「前任」紀錄供顯示，權限全失；山寨依 §5.2 選址。
- 正式勢力（有國家、`npc`／`player`）不直接落草，必須先經原解散／分裂流程成為 rebel 或失去國家。

## 10. 玩家

- **開局：** 主選單「中立 / 自建勢力 / 加入情境勢力」之外新增 **「落草」**：玩家為頭目、1 人伙、kind bandit、信譽起始 −20、山寨在起始 Site。只在情境允許（情境旗標 `allow_bandit_start`，預設 true）時顯示。
- **遊戲中：** 中立玩家或自建勢力玩家可明示選擇落草（自建勢力須先符合 §9.2 條件）；受控人物從不被自動成伙。
- **招安：** 玩家頭目收到招安提議時出選項；玩家作為正式勢力首長／官員時可對同 Site 土匪頭目提招安，分數照 §6 算。
- **顯示：** 名冊與 WORLD 瀏覽中 bandit 用灰褐系色與「匪」標記；山寨在 Region 地圖上只對「已知」方顯示。

## 11. NPC AI 與畫面外

- 頭目每日一次簡化決策（沿 11.6 每勢力每日一個主動動作的基線）：依序考慮 換寨（heat ≥ 70 且 10 日內被官方攻打）→ 起義（§9.1）→ 接受招安（有提議時）→ 蟄伏（heat ≥ 70 未被攻打）→ 勒索（到期的聚落）→ 劫掠（選已知最近、戰力比最佳的在途隊伍或聚落倉庫）→ 休整。
- 劫掠距離：目標在山寨 2 Site 距離內；出手門檻：己方戰力 ≥ 目標 1.2 倍。
- heat：每次劫掠 +10，每次被官方勢力攻擊 +20，每 10 日 −5，下限 0。
- 畫面外戰鬥沿 10A.3 公式戰鬥；玩家在場則走 crowd Site。土匪在 crowd 內是普通敵對陣營，不需要新 AI 類型；只在群體層加「劫完就撤」目標（拿到遺物後退回山寨，不追擊）。
- 「不補造」：10A 沒有逐人模擬的區間不補算成伙、招安與起義。

## 15. 驗收

- **BA-01 白名單**：`kind=bandit` 通過驗證；`bandit` 子表缺鍵補預設；非 bandit 帶 `bandit` 鍵、bandit 帶 `nation_ref` 均 `CORRUPT_SAVE`。
- **BA-02 恆敵對**：bandit 與任何 faction（含 255、含另一伙 bandit）`hostile()` 為 true，`at_peace` false；`propose / declare_war / 歸附` 對含 bandit 的 pair 回明確拒絕碼 `BANDIT_NO_DIPLOMACY`，不寫任何事件。
- **BA-03 不能佔領**：bandit 方攻破聚落守軍後 `settlement.owner_faction` 不變，倉庫走原劫掠入口；建國入口回 `BANDIT_NO_NATION`。
- **BA-04 成伙**：潰逃 ≥ 3 人、7 日未歸、原勢力滅亡 → 一次交易產生 entry、頭目、山寨；受控人物在列時整筆拒絕；< 3 人不成伙。
- **BA-05 招安**：遠端提議拒絕；同 Site 當面提議按分數接受／拒絕；成員逐人跟隨；不跟者 ≥ 3 留原 entry 並換頭目，< 3 潰散；頭目成為軍官無爵位；entry 無人時 `merged`。
- **BA-06 潰散**：頭目無人接任或人數 < 3 → 全員改中立單人隊、entry `extinct`、山寨清除、id 不重用；只剩俘虜不潰散。
- **BA-07 起義**：達門檻後 kind→rebel、子表移除、頭目封王、之後可講和；未達門檻拒絕。
- **BA-08 落草**：rebel 無聚落無封地 30 日 → NPC 自動、玩家選項；kind→bandit、協定終止、提案作廢、信譽 −20、`converted_from` 記錄。
- **BA-09 買路錢與保護費**：戰力比門檻、金額、3 日不重截、30 日保護期；付費後路線折價 0%。
- **BA-10 保存**：bandit entry、山寨、heat 存讀一致；crowd 內土匪陣營本地映射存讀一致；舊檔遷移不產生 bandit。
- **BA-11 聲望**：落草 −20、招安／剿滅 +3 只記一次；招安後信譽照原回升曲線。
- **BA-12 顯示**：名冊、WORLD、Region 地圖的 bandit 色與標記；山寨只對已知方顯示。
