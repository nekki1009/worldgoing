# Army synchronous idle kernel

Thirteen narrow entry points for the original owners, not a new simulation or ECS:

- `advance_prefix`: original `TerrainArmy.prepare_combat` idle qualification and eight writes.
- `fatigue_prefix`: original Lab stationary, exact-zero-fatigue normalization, only after work/supply settlement and with no handled work seconds.
- `pack_instances`: read-only packing of an already ordered page run into the existing 12-float MultiMesh buffer and exact repeated Rect2 bounds. Original row/page/Sprite order, appearance, shader and instance order remain authoritative; missing method/precision support retains `_pack_run_gd`. Invalid/oversized/nonfinite input returns an empty packet. `site_army_buffer_pack_test.gd` compares exact bytes for 1..10000 instances.
- `group_render_rows`: combines the prepared mask/row columns with only the original exception submissions. It reconstructs first-row insertion and ascending original ordinals, then splits contiguous page runs at every different page or original Sprite. It returns a fresh row dictionary, five-integer run spans and prepared count. Inputs are read-only, bounded to 10,000 columns and fully validated before output; duplicate/out-of-bounds indices, mask overlap, invalid types or row ranges reject the packet. No person state, callback, retained cache or renderer object crosses this call. BatchView still owns all MultiMeshes, materials and uploads; missing/disabled support uses the original GD grouping.
- `render_idle`: read-only projection of already-admitted stationary ordinary people into fresh presentation buffers. It borrows the original Site's appearance publications only when the original pure appearance callback is still installed. Changed appearances, movement, short visual events, live/Sprite rows and unsupported inputs stay on the original GD path.
- `capture_columns`: read-only original `combat_can_act` qualification into call-local ordinal/64-bit identity/cell columns for the existing `SiteExchangeSnapshot`.
- `capture_people`: the same qualification into the original `_exchange_people(false)` Dictionary interface, preserving String key insertion order, original owner references and null readiness. Eager actor/Army readiness and post-melee weapon callbacks stay in GD.
- `empty_cargo_prefix`: after melee and its signals, skip only consecutive captured ordinals from one original owner whose current cargo is absent or an empty Dictionary. Read-only inputs and at most 10,000 rows/ordinals; owner change, nonempty cargo, malformed rows/indices or unsupported cargo stop the prefix before the original GD weapon query. Snapshot tries once per contiguous canonical Army owner, respecting `native_queries_enabled`; actors, custom scripts, missing methods and remaining rows use the original GD checks. No ammunition classification or person pointer survives the call, and no callbacks or world writes occur inside it.
- `near_front`: exact Manhattan membership of the original ordered enemy cells against this review's contact cells. It returns a fresh byte mask, not a destination, terrain decision, person or movement claim.
- `encirclement_front`: read-only snapshot columns to the original insertion-ordered enemy-cell dictionary and original-owner contact ordinals. Terrain, membership, work, pinning and claims remain in GD; invalid columns return an empty packet.
- `encirclement_field`: the original ordered reverse BFS over this review's terrain columns and occupied-cell union. Only canonical terrain/army/actor readers qualify. Returns a fresh insertion-ordered distance dictionary; movement still uses the original per-person planner and reservations. Current limits are 1024 cells, 32 path steps and 32 commits per review (the older 512/eight limits below are historical).
- `command_presence`: read-only reference position and exact per-row distance projection for the original Army's command-presence refresh. The original owner still writes its reference and each row's presence in order.
- `advance_recovery_prefix`: extends the same consecutive idle-row loop to stationary, living, non-KO rows with active grace/stun/cooldowns, but no rescue, visual event or pending pose transition. The old `advance_prefix` still retains its zero-only contract.

The first two calls borrow the original row dictionaries, commit complete consecutive rows and return the first untouched ordinal. The caller runs that ordinal's entire original GDScript branch before examining subsequent rows. There are no retained person pointers, copied/mirrored person state, callbacks, threads, new clocks or save fields. Non-idle/moving/KO/rescue rows remain on the existing owner path. Missing/unsupported input types are conservatively rejected to that path.

Phase sixteen reuses each validated FLOAT's public-API storage pointer for the eight `advance` writes, only within that row and only when every timer key already exists. INT slots still use the original Variant conversion. If any timer key must be inserted, the original per-write lookup branch remains unchanged and none of the cached pointers is used. Key-presence, finite/type/read-only/typed guards and original write order remain intact; later aliased rows reacquire their pointers after earlier writes. This is not a persistent cache or another person-state owner.

The render call never changes those rows. Its output is disposable presentation data; fresh buffers do not mutate shared PackedArray/COW inputs. The original ordinal row insertion, page/Sprite run splitting, Shader, CPU double-precision sample selection and float32 Vector2 operation order remain intact. The caller checks float32 Vector2 storage; other precision builds fall back. The native projection is bounded to the current 100x100 Site, at most 10,000 rows and the original 64-pixel cell size. Army's separate `native_render_enabled` switch disables only this projection. Missing DLL/method, custom appearance callbacks and cold/new appearances fall back.

Phase seventeen keeps only the preceding successful exact `(page, direction, age)` atlas sample inside `render_idle`: sequence, frame and pre-scaled anchor scalars. Identical requests reuse those values after every person's original qualification, appearance identity, position and palette checks. A different key runs the unchanged decode, validation and double-precision search; a rejected request does not replace the preceding success. Input atlas data is read-only during this synchronous call, with no external callbacks or mutations. Nothing is retained into another call, so replacing or editing a sample between calls is observed immediately. No phase quantization, animation skipping, person-position reuse or persistent renderer cache is introduced.

The two capture calls first validate a whole query, then return fresh query-only buffers/dictionaries. At most 10,000 rows, equal row/cell lengths, exact ordinary field types and finite numeric HP/KO are admitted; unusual coercions conservatively reject the whole query to GD. No `member` filter is added: the original predicate also admits non-members, movement, guard/rescue and cooldown states when HP/KO/pose/captivity/departure permit. Negative cells and full 64-bit IDs/factions are retained. Army's `native_queries_enabled=false`, a missing method or any script subclass uses the original GD loop; the subclass guard preserves overridable qualification/identity callbacks. There is no retained roster, cross-query cache, reduced frequency or change to action/readiness/event order. An empty materialized result runs the original empty GD scan too; it cannot omit a qualifying person.

The implementation uses [Godot's public C interface](https://docs.godotengine.org/en/stable/engine_details/engine_api/gdextension/gdextension_c_example.html). The vendored MIT-licensed header is generated by the installed Godot 4.7.2 executable, not a private engine layout. `variant_get_ptr_internal_getter` is used only after checking types; row pointers are discarded before advancing. Existing slot pointers are reused only when no key insertion occurs. Lookup StringNames do not change original String keys or insertion order. Integer and IEEE signed-zero cases are tested.

## 2026-09-15 synchronous parallel projections

`render_idle` and the two capture methods now split at least 1024 rows into four disjoint ranges using the existing `WorkerThreadPool` public native-group API. The calling thread joins every group before returning: input dictionaries are read-only, buffers are allocated before dispatch, and only separate output ranges/chunk-local vectors are written. Capture results merge in original ordinal order. Smaller inputs or unavailable worker support use the same serial loop. No SceneTree, renderer calls, gameplay writes, callbacks or jobs survive the join. This supersedes the older module-wide no-threads description; the mutating prefix methods themselves remain serial. See the official [thread-safety boundary](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html).

Command-presence distances use the same public Vector2 methods through their typed call interface, avoiding per-distance Variant boxing without substituting different math. Missing dictionary keys still use checked lookup, never unchecked indexing. Current measured results and failure records are in [the stable-30 continuation](../../output/site_army_stable30_native_20260915/README.md); neither CPU-only checks nor average FPS establish a stable 30-FPS floor.

Additional tests: `site_encirclement_columns_test.gd` (61 ordered comparisons / seven invalid packets), `site_encirclement_field_test.gd` (160 terrain/ramps/obstacle/order cases / nine invalid packets), and `site_army_native_render_test.gd --large` (375000 exact column comparisons across 2500-row parallel calls). `site_army_stable30_orders_test.gd` compares the frozen maneuver implementation with the current implementation under the SAME current review cadence, including state, claims, RNG and custom callbacks.

The front call accepts only Vector2i cell arrays, at most 10,000 cells each, a comparison product at most 2,000,000 and radius 0..8. Signed 64-bit subtraction retains the original full int32 coordinate range. This deliberately bounded loop reuses the existing module and standard vectors instead of introducing another spatial index. Larger contact products, unsupported input, a missing method or `native_front_enabled=false` keep the original GD contact buckets. A conservative scalar bounding box rejects only impossible distant cells. Exact distance qualification, enemy insertion order, all terrain/occupancy/external callbacks and their ordering, 512-cell/eight-step field limits and original eight-step command cap remain with Army. There is no cross-review reuse or parallel mutation.

Phase twenty uses the public `variant_get_keyed` result/validity pair for six read-only `render_idle` fields (pose, visual role, age, identity, atlas page and palette). Each returned Variant is destroyed at that row's scope exit, including every rejection. Absence remains distinct from NIL; original type/finite/admission, appearance identity, position, sample and palette checks stay intact. The mutable `field` helper, write pointers, simulation and other entry points are unchanged. The render test adds 24 missing/NIL/wrong-type/StringName cases plus typed/read-only inputs and IDs beyond double's exact integer range. Actual FPS and full-pixel evidence are in [phase twenty](../../output/site_army_scale_phase20_20260915/README.md); this is not a persistent cache or a new owner.

Phase twenty-four's smaller, uninitialized row-local slot arrays were tested and withdrawn: six original-main trials averaged 24.354 → 24.601 FPS, but the prespecified extra pair regressed 1.21%. The active C++/DLL remain phase twenty-three. Sixteen optional timer-presence combinations and four absent required fields were added to the idle boundary test and pass on both candidate and restored DLLs. See [the complete trial and restoration record](../../output/site_army_scale_phase24_20260915/README.md); no phase-twenty-four FPS improvement is claimed.

Phase twenty-three adds only the post-melee empty-cargo prefix above. Original-main 5000-person ABBA (60 wall seconds each) measured 22.989 → 24.877 FPS (+8.21% in this set), still below 30 FPS; 200-person ABBA was 95.611 → 97.064 with overlapping ranges. A uses the saved old DLL plus a frozen Snapshot loaded only in benchmark memory; B uses the candidate DLL and Snapshot. Full provenance, callback/fallback/state tests, uninstrumented trials and actual-main pixels are in [phase twenty-three](../../output/site_army_scale_phase23_20260915/README.md). Dense armed-ranged FPS and export packaging remain unverified.

The recovery entry point receives the original owner's stun recovery rate. It validates an entire row before the first write, then applies age, four cooldowns (including the original 1e-9 cleanup), grace, stun and think in original order. The all-zero path retains its positive-zero normalization and avoids unnecessary recovery arithmetic. It reuses checked original Dictionary slots only when no key insertion can occur; otherwise each write reacquires its slot. Aliased rows see prior writes. Movement, KO/wake, rescue, visual/pose transitions, HOLD and legacy combat still run in the original owner. Army subclasses retain overridable visual/pose callbacks via the old path. `native_recovery_enabled=false` or an older DLL without the new method uses `advance_prefix`; `native_idle_enabled=false` disables both. There are no new clocks, retained pointers, threads, owner mirrors or save fields.

The presence call admits at most 10,000 rows with finite ordinary numeric values and exact field types. Reference membership deliberately includes KO/get-up members; active presence does not. Per-axis double-precision medians, the nearest actual person and full 64-bit ID tie breaks preserve original ordering. Stationary half-cell centres are exact in the admitted coordinate range (-10,000..10,000); moving coordinates are supplied by the original `combat_ground / CELL_PIXELS` expression, including both movement curves. Distance and squared-distance use Godot's public Vector2 methods, not a replacement sqrt or squared-radius comparison. Fresh reference/distance buffers are discarded after the refresh; no person data is retained across calls. Radius and the two-cell hysteresis are evaluated in GD immediately before each original `present` write, preserving aliased dictionaries. Empty reference leaves the prior reference vector unchanged. Missing native support, disabled `native_presence_enabled`, unusual input/coercions, Army subclasses, a live player member, non-64-pixel cells or non-float32 Vector2 builds retain the complete original method. Read-only/typed rows are never mutated through native pointers; original GD write enforcement remains intact.

From the repository root in PowerShell: `& tools/build_army_idle.ps1`.

The bounded 60-second build uses already installed MSVC x64 Build Tools and Windows SDK, `/O2 /fp:strict /MT /W4 /WX`. No package download, godot-cpp, project SDK change or Godot engine rebuild. Intermediate outputs and per-build logs stay under `.godot-temp/army_idle_build`; only a successful DLL is copied to `bin/army_idle.windows.x86_64.dll`. Close active game/editor instances before rebuilding a loaded DLL. Compiler failures do not publish a replacement.

Currently built and runtime-tested on Windows x64, Godot 4.7.2 Mono. The descriptor's API minimum is 4.4; this is not evidence of testing every Godot version, platform or exported build. These entry points do not change the existing C# query kernel. The current project file targets Godot.NET.Sdk/4.7.2, updated by the editor before phase fifteen; the grouping change does not edit that SDK. Export/package verification is still required before distributing this native library. The GD branches remain available through the existing-owner `native_idle_enabled=false` switch; do not infer cross-platform packaging support from that fallback test.
