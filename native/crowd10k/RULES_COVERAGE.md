# crowd10k v2：規則覆蓋表

2026-09-29。這張表對照現行正式規則，說明 `native/crowd10k` 原型移植了哪些、怎麼移植、哪裡做了簡化、哪些沒有納入。

**範圍說明（依 Astra 審查修正）**：✅ 代表「規則已移植，而且有對應的公式比對或情境斷言」，不代表已經跟正式 Godot 流程逐步對照過。流程順序的差異，只有寫了斷言才會被抓到；這次審查就找到兩個（三陣營判敵、同輪疲勞），都已修正並補上斷言。

依據：
- `SITE_COMBAT_DESIGN.md`（D01–D79）
- `SITE_COMBAT_EXCHANGE_V1.md`（2026-09-14 起的相鄰交鋒制，含 09-18、09-25 的修訂）
- `SITE_COMBAT_INSTITUTIONS_V1.md`（§4 士氣、§6 拘束）
- 程式：`site_combat_rules.gd`、`person_fatigue.gd`、`site_army_ai.gd`、`terrain_lab.gd`（_resolve_exchanges、_resolve_ranged_*）、`terrain_army.gd`（exchange_*、apply_unit_contact、settle_combat_command 等）

符號說明：
- ✅ 照規則移植
- ≈ 規則相同，但把「格」換成連續距離，或改用等價的近似做法（見說明欄）
- ⏸ 沒有納入

## 流程規則

| 規則 | 狀態 | 說明 |
|---|---|---|
| 每人每秒至多參與一輪交鋒；同輪與所有合格相鄰敵人各比一次，逐對累計後一次提交（09-25） | ✅ | 10 Hz 全域輪；平行收集配對，再依固定順序合併提交；測試驗證冷卻違規為 0 |
| 「四向相鄰」且原 `can_attack_across` 合法 | ≈ | 改為中心距離 ≤1.15 格，且兩人之間有合法直線（懸崖、水、岩石都會擋）；測試驗證懸崖不能交鋒、坡道可以 |
| 發起資格：接敵／追擊令且有指揮者；MOVE 遭遇；HOLD 無指揮時近身自衛；潰退不主動 | ✅ | `initiates()` 逐條對應 `exchange_initiates` |
| **MOVE 遭遇**：遇敵交戰、同一輪處理所有接觸的敵人、接觸期間暫停、接觸解除後繼續原命令、不離隊追敵 | ✅ | 2026-09-29 補斷言，比照 `site_move_encounter_lab_test.gd`。同時修正：只要有隊員在近戰距離內（S_FIGHT），整隊就暫停；原本只在交鋒後 0.4 秒內算接觸 |
| **陣營**：用完整陣營編號判斷敵我，可以有三方以上 | ✅ | 2026-09-29 修正：原本用 `team & 1`，陣營 0 和 2 會被當成同一邊。現在查 256×256 關係表：預設不同陣營即敵對，同盟可設定；同盟視同友軍（不交鋒、火控、推擠）。斷言涵蓋陣營 0／2／5 三方互戰、非連續編號、同盟擋射線 |
| 準備狀態：硬直、冷卻、救助、擊退中不能發起；仍可受擊 | ✅ | |
| 具指揮能力者自動技能：多向受敵選穩守，否則強攻；8 秒冷卻 | ✅ | |
| 暈眩門檻 100；受擊後 3 秒寬限，之後每秒 −10 | ✅ | |
| 擊暈 4 遊戲小時；倒地時再受衝擊，重設等待時間（不累加） | ✅ | 用 Site 時鐘換算遊戲時間：`combat_left` 大於 0 時 1:1，歸零後 1 秒＝60 遊戲秒，另乘 Site 倍速（P1） |
| 自然醒來：暈眩設為 30，起身 2.2 秒，不回 HP | ✅ | |
| HP 歸零才算死亡；死亡優先於擊暈 | ✅ | |
| 倒地者、死者不再占站立位置 | ✅ | 推擠會略過倒地者；倒地者仍可能被箭射中 |
| 救助：HOLD、閒置、附近沒有敵人；相鄰友軍連續 4 秒，把昏迷縮成 ≤1 小時；受擊或雙方失效就中斷 | ✅ | 2026-09-29 起，救助同時止血；昏迷剩不到 1 小時但仍在失血的傷兵，也可以救 |
| **倒地失血（2026-09-29 使用者決定）**：昏迷期間每遊戲小時 −25 HP，直到被救或被俘；HP 歸零即死亡 | ✅ | 交戰時 1 現實秒＝1 遊戲秒，脫戰後 1 現實秒＝1 遊戲分鐘（`cfg.time_scale`）。失血不算「有效受擊」，所以不會中斷正在進行的救助，也不會重設昏迷時間；倒地後再受傷會重新開始失血；失血死亡照一般死亡扣士氣 |
| **AI 走去救傷兵（2026-09-29 使用者決定，預設開）** | 新增 | `cfg.rescue_seek_cells = 8`：守位中的閒置隊員會走到 8 格內的傷兵旁救助；設 0 回到原規則（只救相鄰） |
| **AI 自動俘虜（2026-09-29 使用者決定，預設開）** | 新增 | `cfg.auto_capture`、`capture_seek_cells = 8`。條件：隊伍由 AI 控制、守位、未潰退；士兵閒置、沒有敵方目標、看守未滿 4 人；目標是倒地且未被俘的敵人。走到身邊後貼身 4 秒，跟手動命令相同；同一步先處理救自己人。玩家隊伍不會自動俘虜 |
| 遠程：發射時就扣彈、不退還；冷卻 2／3 秒；硬直 0.25／0.4 秒 | ✅ | |
| 遠程：相鄰有敵人時強制近戰、不射箭 | ✅ | |
| 遠程火控：射線上有友軍（包括昏迷的）就不射 | ✅ | |
| 遠程：抵達時才判定，射線上第一個身體攔截（友軍也會中箭） | ✅ | 同一步抵達的箭共用一份占位快照，依發射序號處理 |
| 遠程：尋找安全射位、保持至少 3 格 | ≈ | 過近就後退；射線被友軍擋住就左右側移（限在 6 格內） |
| 士氣：死亡 −40×n／事件前存活編制；擊暈 −20×n／…；指揮中斷 −10；統御最多減免 25% | ✅ | P1 改成照 `_observe_team_life`：每步開頭跟上次檢查點比對（先暈後死只算一次死亡），分母含昏迷者與俘虜，−10 在同一次事件裡扣。俘虜是否計入分母，依據 `_life` 不看俘虜狀態，`site_sustain.gd` 本身未對照 |
| 潰退：士氣 ≤20 就撤離最近的敵軍；重新集結要 30 遊戲分鐘安全整補、士氣 ≥50，並重新下令 | ✅ | P1：整補 +5／遊戲小時適用於任何「安全、停止」的隊伍，不限潰退中；安全＝8 步內沒有能行動的敵人、腳下沒有箭飛過；集結計時用遊戲時間 |
| 在場判定：參考點取存活成員實際位置；半徑＝站位包圍半徑 +2，至少 8 格；已在場者再 +2 緩衝 | ✅ | |
| 接任順序：正式隊長 → 合格代理轉正 → 依順位找合格幹部 → 隨機抽合格隊員；D39／D40／D47／D48 | ✅ | 測試涵蓋：隊長死亡、幹部代理、全員失能後指揮空缺 |
| 首次取得職務才生成指揮能力（各 0–100 均勻隨機） | ✅ | |
| 無人指揮：停止主動進攻、需要重新下令；只剩近身自衛 | ✅ | |
| 戰術：命令準備與補位間隔最多縮短 20% | ✅ | 套用在下令延遲、槽位壓縮、包圍檢查的間隔 |
| 戰術 AI（每 0.5 秒）：休整、待機、追擊、接敵、接近、等待通路 | ✅ | 常數與判斷順序照 `site_army_ai.gd` |

## 沒有納入

| 項目 | 原因 |
|---|---|
| 玩家操控、Q／E 技能、玩家不被 AI 接管 | 需要接到 Godot 的輸入；原型沒有玩家 |
| 隊長與特寫人物的 live 3D、動畫取樣 | 這次明確先不處理圖形 |
| 口糧、缺糧、交付、搜刮、贖回、裝備封存包 | 屬於後勤與經濟系統，戰鬥期間只會按遊戲小時緩慢變動 |
| 攻城武器、木柵施工 | 首版近戰切片本來就不做；設施加成的欄位已留好 |
| 精確武器幾何命中（D63–D67 的掃掠） | 正式模式已經改成交鋒制，舊的精確路徑只保留給歷史測試 |
